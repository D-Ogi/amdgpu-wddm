# M340 - PSP first/warm comparison and RLC retirement observer

Compared the same104 binary's successful first startup (M328) with its failed warm startup (M332). All11reported commands match in index/id/firmwaretype/size/rc/status/returnedTMRaddress. Every command reports rc0/status0; elapsed times differ. This rules out a reported PSP command rejection or a changed reported command sequence in this pair, not firmware execution problems or unlogged command payload differences. Source logs and derived commands.json are linked by source hashes.

Regcalc-derived E28 extraction finds RLC_CNTL read/write events for firstload,unload,reload, but no complete GRBM_STATUS2 records in these streams. Incomplete first/unload lines and final transport loss prevent treating absence as proof of no hardware access. The AMD gfx_v10_0_soft_reset path inspects GRBM_STATUS2.RLC_BUSY and stops RLC/CP/MEC before applying its computed reset mask. This is distinct from the unused ordinary-resume reset callback reviewed in M335; it is a recovery branch, not proof a reset must be added to normal initialization.

Added RlcRetirementSnapshot after existing undo and default bank restoration, before teardown. Reads RLC_CNTL and GRBM_STATUS2 through the EXISTING safe-read table; logs raw values and separate status codes. Named offsets generated from original AMD headers. No write-table change, new MMIO write, polling, delay or altered quiet/resource-release predicate. Updated stale shim comment to recognize E28's actual SMU-layer RLC stop.

Deterministic generation passes; WDK26100 build/signing pass. Development SYS D109A86E828908F0E93D046A6370976EC0FFE2A167B46C4ECFC3138613439C3D with existing105 INF version is not deployed. This is observation preparation, not a repaired warm start or hardware validation of the new reads at this boundary. Lab remains full105 from M339, no lab action in this change.
