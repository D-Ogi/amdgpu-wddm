# M281: bounded transpositions for oversized page cycles

Date 2026-09-23. Base commit bed764da5192be7132d646be0e6331c1edeb30fd, captured working-tree sources. No lab operations or deployment.

PagingPermutationPlanBounded preserves minimal cycle execution when length+1 actions fit fresh hardware capacity. Larger cycles become forward pivot transpositions: SAVE pivot, COPY successor to pivot, RESTORE saved pivot to successor. Each three-copy group ends scratch lifetime. A cycle of N pages costs3(N-1)copies in this fallback versusN+1 for the normal route. This removes the single-cycle hardware-buffer-size limitation without carrying scratch values across jobs. A buffer must still accommodate one transposition.

Integrated in GfxPagingBuildPermutation and WddmBuildPhysicalTransfer. A tagged opaque resume token (bit31 plus next action index) distinguishes group resumes from ordinary page tokens; terminal token remains page count. Endpoint preparation uses zero progress for tagged tokens and permits them only in the alias path. Partial results publish complete groups and resume by action index; diagnostic logical byte count is reported once the entire plan has been built, not for staging traffic. This supersedes M280 seed-token/proportional-byte accounting. Metadata is rebuilt on each callback; no MDL pointer is retained. CPU cost for very large multi-buffer requests needs future profiling/architecture work. Stable endpoint identity/lifetime across real OS callbacks remains an acceptance requirement.
