Date2026-09-23. Base commit bed764da5192be7132d646be0e6331c1edeb30fd, captured working-tree sources. Host-only planning foundation, no lab access or deployment.

Inspected local Microsoft fields: TransferSize is in bytes, TransferOffset applies to segment endpoints, MdlOffset selects PFNs in pages; virtual transfer size is in bytes. The inspected fields do not state that every request length is page-multiple. This is not a claim that all unaligned alias patterns have been observed from Windows. Source excerpt/hash in reference.txt; original docs revision7515063cea4c9e98db6a92986c5b4ddb0463fd16, enriched WDK26100 declarations.

PagingPageBands partitions a request with equal source/destination in-page offsets into at most three disjoint physical byte-offset intervals. For each interval it returns FirstPage/PageCount, Offset and Bytes. Only the pages intersecting the request in that interval are selected. Different bands never alias bytes even when their physical page identities overlap; each band can use the existing graph planner with its own uniform copy length. This avoids expanding page identities into one metadata node per byte. It does not handle differing source/destination offsets.
