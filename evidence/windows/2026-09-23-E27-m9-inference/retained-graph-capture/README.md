# Immutable physical graph capture and resumed planning

GfxPagingCaptureVirtualGraph resolves complete equal-offset VA ranges under the GFX builder lifetime lock into one allocation (header plus136bytes/page). It retains normalized physical identities, consistent local/system access domain and logical edge indexes, preflights every byte band and derives the maximum atomic group from the real packet-size query and ring capacity. Caller receives ownership only on success. A physical identity mapped simultaneously with conflicting local/system domain is currently refused; this is an unresolved alias/cache policy, not a hardware limitation.

GfxPagingPlanCapturedGraph returns a batch descriptor and proposed next cursor using captured indexes only. It performs no translation and does not advance owner progress; the caller must publish before committing the proposed cursor. Planner workspace and move storage are reused inside the capture. The capture owner header now records its pool tag, and actual cleanup frees with that tag.

Six new fixtures exercise system, mixed and local three-page cycles, full and offset17partial ranges. After capture/owner attachment, translation is disabled and the VA fixture is replaced. Complete graph batches still match the initial byte snapshot, including untouched bytes, while scratch is overwritten between batches. Zero capacity leaves progress unchanged. Detach precedes metadata release, and pool/lock accounting returns to baseline. These are actual capture/resumed-planner tests with synthetic translations; there is no retained-path packet emission or GPU execution acceptance yet. Existing actual-walker and packet tests remain in the default suite.
