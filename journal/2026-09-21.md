- NVMe in unit A: the firmware does not list the disk. Measured from the probe with the SSD in the slot: the M.2 root port is `00:15.0` (FCH, LnkCap 5 GT/s x2), bus 03 behind it is empty, `LnkSta = 0x1100` (no speed, Data Link Layer Link Active clear) where the Ethernet port `00:15.1` shows `0x3011`. A secondary bus reset changed nothing; a retrain request left `0x1900` (Link Training set, never completes). So the port finds no link partner: this is below the firmware and the OS (seating, power to the slot, the SSD itself or the slot), not a boot-entry problem. The same SSD works in a USB enclosure on the dev PC.
- Correction to the entry above: after one more cold start the link came up and the board boots Windows from the NVMe (the owner saw "Getting services ready", i.e. the `specialize` pass). Nothing else was changed in between, so link detection on this M.2 port is intermittent with this SSD; to be watched, and measured (`LnkSta` of `00:15.0`) the next time it fails. It also answers the open question: the firmware boots a disk it has never seen through `EFI\Boot\bootx64.efi`.
