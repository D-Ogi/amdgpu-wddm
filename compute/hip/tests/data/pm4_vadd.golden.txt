# pm4_vadd.golden.txt - the expected PM4 dword stream of one gfx1013 compute dispatch.
#
# Section 3.7 of docs/design/m16-hip-route-b.md states the 19 packets. This file states
# the dwords that they must become, so that a change of the order, of a register offset,
# of the shader-type bit, of the entry address shift, of the fence dwords or of the
# padding fails tests/host/test_pm4.c. It was written by hand from the design table and
# then compared with the builder, not dumped from it.
#
# The inputs that tests/host/test_pm4.c passes (all synthetic, no device). Every address
# has bit 40 set and no byte of it repeats, so a wrong shift or a swapped dword shows:
#   entry_va              0x00000140ABCD1E00   (256-byte aligned, as COMPUTE_PGM_LO needs)
#   kernarg_va            0x00000140ABCD2000
#   fence_va              0x00000140ABCD3008
#   fence_value           0x0000000100000007
#   private segment rsrc  0x00001000 0x00000040 0x00010000 0x1104BFAC
#   grid (workgroups)     4096, 1, 1
#   block (work items)    256, 1, 1
#   compute_pgm_rsrc1     0xE0AF0000   compute_pgm_rsrc2 0x0000008C   rsrc3 0
#   kernel_code_properties 0x0409      user_sgpr_count 6   (bit 10 is wave32)
#   group_segment_bytes   0            dynamic_group_bytes 0
#   flags                 BC250HSA_DISPATCH_GFX_RING
#
# One hexadecimal dword per line, 8 digits. A line that starts with # is a comment, and
# text after the dword is a comment as well.
#
# "Gdzie drwa rabia, tam wiory leca" - where wood is chopped, chips fly: a packet stream
# with no golden file is how the chips end up in the shader fetch.
