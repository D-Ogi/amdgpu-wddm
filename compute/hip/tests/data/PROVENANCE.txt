PROVENANCE of compute/hip/tests/data
====================================

These files are test fixtures of layer 1 of docs/design/m16-hip-route-b.md. They are
committed so that the host gate runs on a machine with no AMDGPU compiler and with no
BC-250 adapter. `pwsh compute/hip/build.ps1 -Rebuild` builds the two binary files again
and compares the SHA-256; it reports a difference and keeps the new file.

Compiler
--------

  clang version 22.1.8
  https://github.com/msys2/MINGW-packages d34feaaa1d0aff624c870910b6f2589aa40d20de
  Target: x86_64-w64-windows-gnu
  Local path: toolchain/llvm-amdgpu-22.1.8/mingw64/bin/clang.exe

The compiler is the portable AMDGPU clang of this workspace. It builds device code only.
The library, the host tests and hipprobe are built by the Microsoft C compiler.

Commands
--------

  clang -x hip --offload-arch=gfx1013 --offload-device-only --no-gpu-bundle-output \
      -nogpuinc -nogpulib -O2 -std=c++17 -o m16_kernels.gfx1013.co m16_kernels.hip

  clang -x hip --offload-arch=gfx1013 --offload-device-only \
      -nogpuinc -nogpulib -O2 -std=c++17 -o m16_kernels.fatbin m16_kernels.hip

-nogpuinc and -nogpulib keep the ROCm headers and the ROCm device library out: the
kernels use clang builtins only, so layer 1 needs nothing of ROCm to build its fixtures.

The two commands run with the working directory set to this directory, and the output
path is the committed file itself. That matters: clang names the module identifier symbol
__hip_cuid_<hash>, and the hash follows the output path. The same source built into
another directory gives a code object of the same size whose .dynstr and whose two hash
tables differ (measured, 2026-10-08). This is also why the device entry of the fat binary
is not byte for byte the standalone code object: the two clang invocations write two
different output names. tests/host/test_unbundle.c therefore compares what the entry
holds, not its bytes.

The hash does not follow the content of the source. A change that touches only the
comments of m16_kernels.hip leaves both artifacts byte for byte the same, which is why the
source hash below can move while the two artifact hashes stay (measured, 2026-10-08).

Why these three kernels
-----------------------

Each one answers one question of the step-1 lab trial:

  vadd           a clang-built code object runs at all, with explicit arguments only.
  reduce256      the computed COMPUTE_PGM_RSRC2.LDS_SIZE is right (decision 3 of the
                 design): the kernel uses 1024 bytes of local memory and the kernel
                 descriptor holds LDS_SIZE 0.
  writeGridSize  the implicit argument block is filled from the metadata list and not
                 from a structure: the block of this kernel holds 13 hidden fields, and
                 two of them meet at one byte boundary. The kernel returns
                 block_count_x, _y and _z, which is the work-group count of the
                 dispatch (AMDGPUUsage.rst: not the grid in work items).
