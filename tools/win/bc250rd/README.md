# bc250rd - read-only register reader for Windows (experiment E02)

| File | Purpose |
|---|---|
| `driver/bc250rd.c` | Software-only WDM driver. Does not bind to the GPU (the Basic Display driver keeps it), finds `1002:13FE` in PCI configuration space, maps BAR5 **read-only**, serves 32-bit reads for offsets in the allow-list. No write path to the GPU exists |
| `driver/allowlist.h`, `reglist.txt` | Generated by `gen_allowlist.py` from the Linux reference sweep (E03): 5542 named registers, 5398 offsets that were read on unit A before any driver without harm |
| `app/bc250rd_cli.c` | `info` and `sweep`: prints `<ip>.<name> <offset> <value>` exactly like the Linux sweep logs, name first, value after the read, so a hang names its register |
| `temp.sh` | Run on the development PC: temperature of the target over SSH |
| `build.ps1` | Builds both without a WDK installation (WDK and SDK NuGet packages unpacked on a data disk) and test-signs the driver with a self-signed certificate |

Why an allow-list inside the driver: on this SoC a read of the wrong BAR5 address hangs the machine
(`docs/facts.md` M16). A generic "read physical memory" driver would also be a dangerous thing to publish;
this one can read 5398 fixed offsets of one PCI device and nothing else.

## On the target (elevated, test signing on)

```powershell
sc.exe create bc250rd type= kernel start= demand binPath= C:\BC250\bc250rd\bc250rd.sys
sc.exe start bc250rd
C:\BC250\bc250rd\bc250rd_cli.exe info
C:\BC250\bc250rd\bc250rd_cli.exe sweep C:\BC250\bc250rd\reglist.txt GC.    # run it through SSH, log on the other side
sc.exe stop bc250rd
```

## Temperature

`bc250rd_cli temp [count [interval_s]]` prints the SoC temperature (Tctl). Windows offers no ACPI thermal
zone on this board and amdgpu never reads the thermal block through MMIO, so there was no proven BAR5 path.
What is proven on this unit is the path of Linux' `k10temp`: SMN register `0x59800` (`THM_TCON_CUR_TMP`)
through the root complex's SMN index/data pair in configuration space (`00:00.0`, `0x60`/`0x64`). The driver
does exactly that, for an allow-list of one SMN address. It is the only write the driver issues, it goes to
the host bridge's index register (restored afterwards), never to the GPU. First reading under Windows, idle
desktop, Basic Display driver: 73 C (Linux after the fan was flipped: 72 C at the 1500 MHz idle level).

## Limits

- Configuration space is read with `HalGetBusDataByOffset`, a legacy interface. Fine for a measurement
  tool that must stay out of the device stack, not for a product driver.
- Banked registers are read in whatever bank `GRBM_GFX_INDEX` currently selects; selecting a bank is a
  write and this tool does not write.
- Not yet run on hardware. Built and signed only.
