## Invocation and bounds

Local validation only (no target discovery, secrets, UI or network):

```text
python -B scratch/gui/codex/run-trial.py --config scratch/gui/codex/candidate.json --check
```

After admission, the lead uses the same command with `--execute`. The host
copies only the chosen wrapper, common/firewall helpers and config through
`target.py`; it does not supply candidate artifacts or an adapter.

Each lab wrapper accepts `-Mode <mode> -ConfigPath <absolute-lab-config>`.
The public sequence, through `target.py ps`, is `Prepare`, `Start`,
`Observe`, optional `Stop`, `Observe` until `can_cleanup=true`, then
`Cleanup` with a `cleaned` receipt. `Stop` is asynchronous. `Supervise`,
`Worker` and `Guard` are internal modes, not operator entry points.
The host runner performs this sequence and reserves fresh local/remote output
directories; never reuse a stage directory or overwrite its evidence.

The absolute lab clock starts at Start. Work stops by duration minus 20 seconds,
the child deadline is duration minus 10 seconds, and closure/cleanup must fit
inside the total duration, at most 180 seconds. End early once objectives are
met. The host's bounded post-Stop observation window does not extend lab work.
No kit reboots Windows, restarts DWM or restarts the device. The lead plans
required Windows restarts between fully closed stages.

For `resume`, `verify`, `observe-40`, `observe-24`, add
`previous_result: {path, sha256}` naming the preceding stage's preserved
lab `result.json`. It must be `evidence-ready`, from the same trial family
and a different boot. CU observation additionally requires the corresponding
`request-40` / `request-24` predecessor. For L5 the operator must choose
the correct predecessor in the chain below; the generic gate does not validate
the L5 predecessor stage name.

not PASS: `host-result.json` deliberately leaves `acceptance_pass=false`.

## L-CU independent safety and host evidence

Every L-CU config adds:

```text
thermal: {mode: "local-cli", cli_path: "<absolute lab CLI path>", cli_sha256: "<SHA-256>"}
```

The lab SYSTEM supervisor reads the pinned CLI's `telemetry 1` before GUI
launch and about every two seconds, each read bounded to three seconds.
A temperature >=87 C, missing/stale or implausible reading stops the trial.
This does not depend on the GUI or a working host connection; no direct SMU
writer is involved. Follow the existing lab stop/cool-down procedure.

The host announces preparation on the overlay before Start, then waits for the
running acknowledgement before screenshots or plug sampling. Screenshots use `scale=0.5`, never full size.
L-CU collects raw smart-plug watts at start and about every 15 seconds; preserve
the calibration warning and unknown measurement age. Missing power collection
fails this kit. Watts neither prove a fresh reading nor replace temperature or
OS responsiveness. The reference "+30 W at 1500 MHz" is not a PASS threshold.
The runner does not operate the power relay.

The host captures initial/terminal images and bounded infrastructure stage events.
These do not replace the L1 per-language pictures or other scenario-specific proof;
the operator/adapter must collect those at half scale within the active stage.

## L-OFF fields and cleanup

Add `offline` with `local_subnets` (array of operator-supplied current interface
CIDRs), `management_address` (the host management peer's numeric address inside
an allowed subnet), `external_probe_address` (operator-selected reachable
numeric address outside those subnets), and `external_probe_port` (1..65535).
Use the configured target mechanism; do not hardcode a lab address. Allowed
CIDRs must match current preferred interface prefixes exactly; /0 is refused.
Supply the actual local IPv4/IPv6 subnet(s) needed for management. Loopback is
included automatically; all remaining IPv4 and IPv6 addresses are blocked.

Admission requires enabled firewall profiles, local-rule merging, running
firewall service and a successful bounded external positive control. The kit
does not change profile/default policies. It uses two unique owned rules,
records ownership before creation, and serializes creation/removal with a lock
and permanent closed marker. A colliding foreign rule is refused, not deleted.
Supervisor `finally` and a separate SYSTEM watchdog (including startup recovery)
remove only exact owned names/group/description. Never replace this with
"block Any plus allow local", which would also block the local exception.

Retain `offline-before.json`, `offline-isolated.json`, `offline-end.json`,
`offline-owned.json`, `offline-restored-*.json`, `guard-ready.json` and
`guard-done.json` alongside result/logs. Confirm effective owned-rule absence;
"Stop sent" is not restoration. On uncertain child closure or firewall cleanup,
report recovery-required and hand back to the lead before another trial.
