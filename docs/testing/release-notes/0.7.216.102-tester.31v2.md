# Nagi (amdgpu-wddm) 0.7.216.102-tester.31v2

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and Nagi Control App of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes two records
that only this installer and this control program read.

The release before this one is 0.7.216.102-tester.31. This release replaces it. It is a second issue of tester.31
with three fixes. The kernel-mode driver now gives a picture on some monitors that got none from it, and it now
starts after an update on such a computer. The installer now confirms the first start after an installation.
Nothing else changes. The notes of 0.7.216.102-tester.31 list the changes since
0.7.216.101-tester.30, and they apply to this release too, with the changes below.

This release has one flavour, the release flavour. It is signed with our **test certificate** and still requires
Windows test-signing mode. It is not Microsoft-signed and has not passed HLK certification. The user-mode driver
files are installed through the driver package into the Windows DriverStore.

## How to install

The single file `amdgpu-wddm-setup-0.7.216.102-tester.31v2.exe` holds the whole package: copy it to a local folder
and double-click it. Or unpack the whole zip file to a local folder, then double-click `setup.exe` in the folder it
makes. The setup window asks for administrator rights itself. It reads the state of the computer and shows what it
will change. Your click on Install is your consent, and the window asks nothing more. It restarts Windows by itself
after a countdown of 15 seconds, and it continues after each logon. On the command line, run `files\install.cmd`
from the unpacked folder as administrator, with all its switches. `INSTALL.md` in the package gives all ways.

- The product version is 0.7.216.102-tester.31v2. Windows reports its driver package version as 40.7.216.102, the
  same number as tester.31, with a newer driver date (10/20/2026), so Windows puts this driver in place of the one
  of tester.31.
- An installation of tester.31 can be updated in place: run this setup over it. You do not have to uninstall first.

## New

- Nothing new. This release only fixes the faults below.

## Fixed

- **Some monitors kept the picture of the boot screen and never showed the Windows desktop.** Windows ran, and
  the mouse and the keyboard worked, but the screen did not change after the boot logo, so the computer looked
  frozen. A monitor can describe the same picture signal twice with small differences, for example
  1920x1080 at 50 Hz once as a standard television mode and once in its own detailed timing. The driver gave both
  to Windows, Windows refused the second one as a copy, and the driver then gave Windows no mode for the screen at
  all. The driver now gives each signal to Windows only once, and it skips a copy that Windows refuses instead of
  failing. We found it with a Lenovo LT2452pwC on DisplayPort. Other monitors with the same kind of description get
  the same fix.

- **After the update from tester.31 on such a monitor, the new driver did not start either.** The driver counts
  each start that Windows does not confirm after a logon, and the third such start is refused, so that a driver
  that fails at each start cannot keep the computer in a loop. With a monitor of the fault above, no start was
  confirmed, and the count went with the update into the new driver, which then refused to start. The same
  occurred when tester.31 was uninstalled first, because the uninstall keeps the driver state for the next
  installation. A new installation of the driver now starts with a count of zero. The settings that you changed
  still go to the new driver.

- **The first logon after an installation did not confirm the start of the driver.** The installer continues
  after that logon and registers its two logon tasks there, after Windows has started the tasks of that logon. So
  the tasks did not run for that logon. The start was confirmed only after the next restart, and one more start
  without a confirmation would have been refused. The installer now keeps the tasks when they are already in
  place. When it registers a task after the logon, it starts that task at once.

## Known issues

- The known issues of 0.7.216.102-tester.31 apply.

- **When Smart App Control is on, Windows blocks this installer.** Smart App Control blocks programs that are not
  signed by a publisher that Microsoft trusts, and this release is signed with our test certificate. The setup stops
  at the step "freeze state writers and publish the protected state handoff before INF staging" with "An Application
  Control policy has blocked this file". The setup window is signed the same way, so Windows can also refuse to
  start it. Turn Smart App Control off before the
  installation: Windows Security, App & browser control, Smart App Control settings, Off. Then run the setup again.
  It continues from the step that failed. A fresh installation of Windows 11 24H2 or later can have it on. This
  applies to tester.31 too.

- **Do not use hibernation with this driver.** The BC-250 has no sleep state other than hibernation, so the power
  button of the case can hibernate Windows. On our board, the first resume from hibernation stopped the GPU and
  Windows crashed with `VIDEO_TDR_FAILURE` (`0x116`), and the next start of Windows did not resume. Set the power
  button to "Shut down" in the power options of Windows, and do not choose "Hibernate". We are working on it.

## Settings affected

- This release changes no setting and no default. The installation keeps the settings that you changed.

## If something goes wrong

- When the driver does not start, send us the text file that the installer names at the end of its run, or the
  support file of the setup window, which holds the same text.

- When the screen keeps the picture of the boot logo after the installation, tell us the model of your monitor and
  how it is connected (DisplayPort, HDMI, an adapter), and send the support file of Nagi Control App.

- Look at the preview of a support file before you send it. When you find personal data in it, do not send the
  file, and tell us in the report so that we can fix the application.
