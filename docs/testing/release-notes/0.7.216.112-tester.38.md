# Nagi (amdgpu-wddm) 0.7.216.112-tester.38

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It
replaces 0.7.216.109-tester.37.

It is signed with our **test certificate** and still requires Windows test-signing mode.

## How to install

If tester.37 is installed, open Nagi Control App, go to the Driver page and select **Install update**. Or copy
`amdgpu-wddm-setup-0.7.216.112-tester.38.exe` to a local folder and double-click it. Or unpack
`amdgpu-wddm-tester-0.7.216.112-tester.38.zip` and double-click `setup.exe` in the folder it makes. You can install
this release over tester.37 or tester.36: you do not have to uninstall first. The setup updates the installed release
and keeps the settings that you changed. Windows reports the driver package version as 40.7.216.112.

## New

- **Some GPU hangs of compute work no longer stop Windows.** When a compute job of a game or an application does not
  end and the driver cannot stop its waves, the driver now resets only that compute queue. Windows then reports a
  driver reset (event 4101) instead of a stop with `0x116`. The work of the hung job is lost, and the
  application usually reports that its device was removed.
- **The driver first tries to reset a hung graphics queue or copy engine.** When the GPU must be reset, the driver
  now first tries to reset the hung graphics queue or the hung copy engine (SDMA) queue. Before, each such hang
  ended in `0x116`. The reset does not work in each case: see the known issue about a GPU fault in one Direct3D 12
  program. [BD-180]
- **The driver reports WDDM 2.9 to Windows.** Earlier releases reported WDDM 2.0. With WDDM 2.9 Windows can put
  the frames of a game on a separate overlay plane of the screen (multiplane overlay), so the desktop window manager
  does not have to copy each frame into the desktop. If a game or the desktop shows a fault that tester.37 did not
  show, you can go back to WDDM 2.0: open a command prompt as administrator, run
  `bc250kmd_cli state set WddmVersionCap 0x2000` and restart the computer. To go back to WDDM 2.9, run
  `bc250kmd_cli state clear WddmVersionCap` and restart. [BD-307]
- **The sign-in screen uses the GPU.** The sign-in screen, the lock screen and the administrator prompt (UAC) now
  use the graphics desktop path when the graphics desktop is running. If one of them fails on that path, the driver
  puts them back on the processor path until the next restart.
- **Nagi Control App in Portuguese (Brazil) and Spanish.** Select the language in Settings.
- **The FSR 4 answer of the driver comes from a table row for each GPU.** The driver gives AMD's FidelityFX upscaler
  the FSR 4 answer from the row of the GPU part in a table. A GPU part without a row gets no FSR 4 claim. On the
  BC-250 the answer does not change. [BD-332]
- **Game logs name the graphics modules and the first faults.** When the game log recording is on, the Direct3D 12
  driver writes the graphics modules that the game loaded, with their paths, and the first faults of the game process.
  This helps with reports of games that close without a message. [BD-332]
- **Hibernation continues when the GPU cannot finish its work.** Before, one unfinished GPU job stopped the power-down
  for hibernation. The driver now completes the power-down, and at the resume it restores the GPU in full when the
  GPU lost its power. This path is not yet tested on a BC-250, so the hibernation known issue below stays. [BD-188]
- **Preparation for video on a second overlay plane.** The driver can now describe a group of two overlay planes for
  YUV video. There is no change that you can see in this release. [BD-223]
- **The driver starts when no monitor is on at power-on.** When the firmware lights no screen, the driver now
  starts anyway: Windows runs, and games and compute work. If the picture does not come when the monitor wakes,
  plug the monitor cable in again. [BD-341]
- **The help of the processor temperature limit tells the margin.** In Nagi Control App, the help text of the
  processor temperature limit now says that with the GPU also at work the temperature can go 2 to 3 C or more above
  the limit, so set a limit at least 3 C below the highest temperature that you accept. The text is in all six
  languages. [BD-349]

## Fixed

- **A start without a monitor no longer counts as a failed start.** The driver now accepts a start in which no screen
  is lit as a good start. Before, the start guard counted such starts as failed, and the third start with the monitor off
  stopped the driver (Code 43) until a tool cleared the count. [BD-343]
- **32-bit Direct3D 11 games use less of their address space.** The driver no longer maps GPU-only memory into the
  address space of a 32-bit process. Unigine Heaven (32-bit, Direct3D 11, 1920x1200) ran out of memory after about
  260 s and did not complete. It now completes the benchmark. [BD-210]
- **Direct3D 12 textures and render targets no longer get a processor view that they do not need.** The driver gave
  each committed 2D texture and render target of a common type a linear layout and a processor view of its full size.
  This used address space in 32-bit games and the linear layout can be slower. [BD-352]
- **3DMark SystemInfo no longer crashes when 3DMark starts.** The 32-bit SystemInfo scan of 3DMark stopped with an
  exception at every start of 3DMark. [BD-347]
- **3DMark SystemInfo finds all the ADL functions that it looks for.** The scan used the ADL functions of the driver
  only when all 16 functions that it looks for were present. The driver now has all of them. The functions
  that the driver does not support return "not supported" and change nothing. [BD-351]
- **The installer's start check no longer waits about five minutes after a step of the Windows clock.** After a power
  loss, or another start at which Windows sets its clock, the check waited about five minutes and then reported
  success. It now finds the start of this boot at once. [BD-335]
- **The check after an installation reports only a final result.** At the first sign in after the restart, the
  installer checks the driver a second time when the first check fails. Nagi Control App now shows a failure only
  when the second check also fails. [BD-359]
- **Game logs no longer show debug messages as faults.** The fault lines of the game log recorded every exception
  of the game process, also the debug messages of Windows. A reader took these lines for a crash, and they used the
  space for real faults. [BD-344]
- **The desktop on the processor route shows its windows again.** On the processor desktop route (after an unclean
  end of the driver, or with the graphics desktop path switched off), the screen no longer goes black with only the
  taskbar, and windows no longer flicker or show empty frames. [BD-292]
- **The processor desktop route also works in the two remaining cases.** When the desktop router's emergency switch
  puts the desktop on the processor, or when the graphics desktop path fails to open inside the desktop window
  manager, windows now show their content. The switch in Nagi Control App sets both copies of the setting. [BD-296]
- **Copies inside one window run on the GPU.** A GDI copy whose source and destination are the same surface (for
  example a window that scrolls its own content) now runs on the GPU in a safe order for overlapping areas. [BD-306]
- **An install that stopped half-way no longer blocks every other setup.** When an install stopped after its first
  step, the uninstaller and the setup of any other version refused to start. They can now continue or cancel the
  stopped install. [BD-298]
- **Vulkan programs no longer fill the temporary folder.** Each shader compile with specialization constants left
  one temporary file in `%TEMP%`. After many such files every compile became slower, and short Vulkan programs used
  a lot of processor time. The driver now creates no such file. [BD-211]
- **Vulkan buffer copies no longer read past their source.** A buffer copy could read up to 12 bytes after the end
  of the source range. [BD-290]
- **Vulkan waits for submitted work return sooner.** A wait for a pending timeline value now returns when the work
  is submitted, as the Vulkan specification says, and not when the work ends. [BD-200]
- **Driver unload leaves no lock behind.** The Direct3D 12, Direct3D 11, Vulkan and OpenGL drivers now remove their
  global locks when Windows unloads them, so programs that load and unload them (for example under Application
  Verifier) do not stop. [BD-315]
- **Direct3D 11 applications give offered memory back to Windows.** When a 32-bit or 64-bit Direct3D 11 application
  offers a resource, the driver now gives its memory to Windows, and the memory use of the application goes down. When the
  application takes the resource back, the driver tells it if the content is gone, so that the application can make
  it again. [BD-309, BD-308]
- **Direct3D 11 shader compiles on worker threads get their memory.** The driver refused the shader memory that a
  Direct3D 11 pipeline compile asked for on a worker thread of the driver. The pipeline was then compiled a second
  time on the thread of the application, under the lock of the Direct3D runtime. The driver now gives that memory to
  the worker threads of the device. [BD-327]
- **Per-application settings for programs with a long path.** The driver also reads the per-application settings
  of a program whose path is longer than 260 characters. [BD-256]
- **A failed allocation open now fails.** The driver refuses to open an allocation that it cannot use, in place of
  a success with no allocation. Before, the frames of such an allocation could disappear. [BD-205]
- **The processor temperature limit stays in force after a failed power change.** tester.37 left the processor at
  its firmware temperature limit until the next restart when a change of the power state failed. [BD-293]
- **The GPU finishes its work before hibernation.** Before the GPU powers down for hibernation, the driver now
  waits a short time for the work that is still on the GPU. Before, one unfinished job made the power-down fail,
  and the GPU could hang after the resume. [BD-188]
- **GTA V Enhanced starts.** The Direct3D 12 driver found no Vulkan device for the adapter in the process of the
  game, and then failed every request of the game. [BD-331]
- **YUV video swap chains no longer remove the device.** When a Direct3D 11 application (for example a browser or a
  media player) asks for a YUV video swap chain or a YUY2 texture that the driver cannot make, only that one call
  now fails. Before, Windows removed the whole Direct3D device. [BD-333, BD-330]
- **The monitor comes back after a DisplayPort re-plug.** After you unplug and plug in the DisplayPort cable, or
  change between DisplayPort and a passive adapter, the monitor gets its signal again. Before, the screen stayed
  without signal until the next restart. [BD-195]
- **The GPU clock goes up under sustained load.** When a game or a benchmark kept the GPU busy for a long time, the
  clock could stay low for the whole run. The driver now raises the clock when the load stays high. [BD-329]
- **The GPU clock goes up faster on a warm board.** From 70 C to 78 C the GPU clock went up slowly,
  one step every 1.5 to 2.3 s. A game that started on a warm board could run slowly for up to 10 seconds. Under 78 C the
  clock now goes to the level that the load asks for, up to 1800 MHz, without these steps. Above 1800 MHz the steps
  stay. [BD-329]
- **The driver log summary shows the sustained clock raise.** `bc250kmd_cli log summary` now always shows if the
  sustained raise of the GPU clock is on, and the reason when it is off. [BD-336]
- **The processor temperature limit goes in at every start.** When the processor did not answer the first query of
  a driver start, tester.37 sent no processor settings for that start: the processor ran at its firmware temperature
  limit (100 C) instead of 87 C. The driver now asks again every second. [BD-297]
- **Processor settings after a driver restart.** When the driver restarts inside one Windows session (an update, or
  a disable and enable of the device), a processor clock limit or undervolt that the processor did not take back at
  the stop is now reset to the values of the Windows start. Earlier releases showed such values as the processor's
  own values. [BD-295]
- **The Settings page of Nagi Control App fits in English.** [BD-291]

## Known issues

- **A restart can stop at a black screen.** On some BC-250 boards a warm restart can, rarely, stop at a
  black screen. Switch the power off and on again to recover. [BD-145]
- **Unigine Heaven (Direct3D 11) scores about 12 % lower than in October.** We measured about 90 frames per second on an
  earlier build of this release and about 102 in October with the same settings. We examine the cause.
- **3DMark Speed Way and Port Royal are not verified on this release.** Speed Way can stop with "Exclusive full
  screen mode is not available" [BD-339], and Port Royal can end without a message [BD-340]. On an earlier build of
  this release we tested two parts of these benchmarks separately: the change of a Direct3D 12 game to exclusive full
  screen, and the byte-exact results of a ray dispatch test (694 values). These tests do not show that the two
  benchmarks now complete.
- **Windows can record a memory warning for a 3DMark test.** Windows can write a memory warning
  (RADAR_PRE_LEAK_64) for the 3DMark workload process. We examine the cause. The memory use of that process is not
  yet measured. [BD-348]
- **Tear lines with vertical sync off in exclusive full screen.** In exclusive full screen with vertical sync off,
  the image can show tear lines at a frame rate above the refresh rate. We think that this is the normal result of a
  present that is not synchronised to the monitor, but we still examine it. Vertical sync on removes the effect.
  [BD-354]
- **A 32-bit Direct3D 12 program can stop at its first shader compile.** Rarely, the first pipeline compile of a
  32-bit Direct3D 12 program stops with an access exception. Start the program again. [BD-215]
- **The processor temperature can go above its limit under a GPU load.** With the GPU also at work, the processor
  temperature can go 2 to 3 C or more above the limit that you set. Set a limit at least 3 C below the highest
  temperature that you accept. [BD-349]
- **With the VRAM setting at its small value, a heavy benchmark can run the desktop out of memory.**
  The desktop restarts once and comes back. [BD-337]
- **The 3DMark launcher can show a white window or an old picture at some window widths.** Make the window
  slightly wider. [BD-338]
- **Video on a hardware overlay plane is not enabled in this release.** A browser plays video through the desktop
  path. [BD-223]
- **If the picture does not come back after the monitor wakes, plug the monitor cable in again.** The driver starts
  when no monitor is on at power-on. If the screen stays dark after the monitor wakes, disconnect the monitor cable
  and connect it again. [BD-341]
- **A GPU fault in one Direct3D 12 program can stop Windows.** If the driver cannot recover the GPU after a fault
  of one Direct3D 12 program, Windows can stop with `0x116`. A complete recovery is planned for the next tester
  release: Windows then removes the device of the faulting program only. [BD-361]
- **Six diagnostic switches are removed from Nagi Control App.** They turned off protections of the driver, and
  one of them caused a GPU fault in 3DMark Time Spy. The switches are "Release imported memory residency" and the
  five "Turn off ... (diagnostic)" switches. A release driver now ignores their names. If an earlier build stored
  one, you can keep the stored value. It has no effect. The switch "Write a replay log" stays. [BD-361, BD-362]
- **Restart Windows after every driver change.** If Windows does not restart after a driver change, the processor
  can stay slow until the next restart. [BD-093]
- **Games with module checks do not start while test signing is on.** The tester package is test-signed, so Windows
  runs in test mode. Games that check the signatures of the modules they load, or that use kernel anti-cheat (for
  example Counter-Strike 2), refuse to start or to join servers in that mode. [BD-160]
- **A program with a window that starts from a path longer than 260 characters can stop at once** in a Windows
  error (TextInputFramework, 0xC0000409). This happens on any graphics adapter. Use a shorter install path. [BD-256]
- **Please report blank taskbar or Start bars,** with the time it happened. [BD-282]
- **Long sessions at 2000 MHz need good cooling.** If your board gets hot, set the graphics clock limit to 1800 MHz
  in Nagi Control App. In a warm room a heavy game can keep the processor at its temperature limit (87 C by default)
  for a long time. This is the limit working as designed. For a cooler board, set a lower processor temperature limit
  (85 C is the lowest).
- Do not use hibernation: the first resume can crash Windows with `0x116`. Set the power button to "Shut down".

## Settings affected

- The installation keeps the settings that you changed.
- New setting `WddmVersionCap`: the highest WDDM version that the driver reports to Windows. The default is `0x2900`
  (WDDM 2.9). The driver accepts the WDDM versions 2.0 (`0x2000`) to 2.9 (`0x2900`), except 2.3. Set it with
  `bc250kmd_cli state set WddmVersionCap <value>`. The driver reads it when it starts. [BD-307]
