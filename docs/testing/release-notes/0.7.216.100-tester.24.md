# amdgpu-wddm 0.7.216.100-tester.24

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.216.100-tester.23. This release replaces it. The notes of 0.7.216.100-tester.23
list the changes since 0.7.216.100-tester.22, and they apply to this release too, with the changes below.

## New

- The `manifest.json` of the package names the source revision of each component and the hash of every file it
  installs. The file `tools/release/release-sources.json` of the repository, at the tag
  `v0.7.216.100-tester.24`, gives every installed file its exact source revision and build recipe. Where a second
  build of that revision gives the same file byte for byte, that file says so. Where it does not, it says why in
  one sentence, so a support report can state what the installed file is without a guess.
- The kernel-mode driver is version 0.7.216.25.

## Fixed

- The driver log keeps the history of a quiet desktop. A support report from a machine that stood idle for an
  hour held about the last 50 minutes of it and not the start, because the driver wrote its regular status block
  every minute. While the GPU is idle the block now comes every two minutes, so the log holds more than an hour
  of a desktop that nobody uses. Under load the block comes every five seconds as before, and the first block
  after the GPU wakes up comes within five seconds. Each change of the GPU clock state still writes its own line
  at the moment it happens.
- Windows puts the speakers of your monitor together with the monitor itself. Before this release the sound
  device of the monitor stood apart from the monitor, because the driver gave the audio part of the card a fixed
  port number. The driver now tells it which port the picture goes out of, so the two belong to one device in the
  Windows sound settings and in a program that lists the devices. The sound itself does not change.

## Known issues

- A program that the router sends to the processor path gets Direct3D feature level 10_0 only. With the release
  setting gpu-default this affects programs whose image the router cannot resolve. Keep the router at gpu-default
  (issue #24).
- Without administrator rights, `bc250kmd_cli clock read` gives no clock and no temperature. Use
  `bc250kmd_cli dpm` in its place (issue #7).
- The desktop compositor composes a full-screen game again while another window covers part of it, for example a
  notification. The driver has no overlay path for such a window yet.
- A screenshot or a screen recording of a full-screen Direct3D 12 game can be black. The game puts its own
  picture on the screen, and the compositor does not get the frames. To record such a game, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for it.
- A later release can give a file a new hash although the code inside it did not change. The build recipes of
  this project now make the same bytes from the same source code in any build folder, and the name of the folder
  a file was built in no longer reaches the file itself. This release does not rebuild a file for that reason
  alone. Of the 86 files of this package, 75 are the files of 0.7.216.100-tester.23 byte for byte, and each file
  with a new hash holds new code, a new version or new text.
- The catalog file of the kernel driver (`bc250kmd.cat`) is still different in every build, because every build
  signs a new one. The driver image is the same in every build.
- The known issues of 0.7.216.100-tester.23 apply.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.
- The port of the monitor in the sound device of the monitor is `EnableDpAudioContainerId` (`REG_DWORD`) under the
  `Parameters` key of the driver. 1, the default of this release, writes the port. 0 keeps the fixed values of
  earlier releases. The value takes effect at the next start of the graphics driver, which means a Windows
  restart.
- `EnableRingVmFlush` (`REG_DWORD`) under the `Parameters` key of the driver is an experiment of this release and
  is off. It gives the graphics engine a second way to receive the page tables of the program that is drawing. The
  installer does not write the value, and with it absent or 0 the driver sends the very same commands as version
  0.7.216.24. On the lab machine it ran for about 81 minutes, three ray-traced game sessions among them, with no
  freeze and no lost picture, and a ray tracing test gave 18.74 to 18.81 pictures a second with the value on
  against 18.73 to 18.85 with it off, which is a difference of 0.6 % and inside the spread of repeated runs. So
  it costs nothing that we can measure, and it gains nothing either. If you try it, keep `TdrDelay` at 10
  seconds, and set the value back to 0 and restart after any freeze of the picture.
- `TdrDelay` stays as 0.7.216.100-tester.23 set it: this release writes 10 seconds, keeps a waiting time that you
  set yourself, and the uninstaller puts the earlier value back.
- The shader cache of the 64-bit Vulkan driver is on, as in 0.7.216.100-tester.23.
  `MESA_SHADER_CACHE_DISABLE=true` in the environment of a program turns it off for that program, and
  `MESA_SHADER_CACHE_DIR` puts the cache somewhere else.
- The graphics settings are `REG_DWORD` values under `HKLM\SOFTWARE\amdgpu-wddm\Graphics` for all games and under
  `HKLM\SOFTWARE\amdgpu-wddm\Graphics\Applications\<program file name>` for one game. No value is set after the
  installation, so each game keeps its own settings until you change one.

## If something goes wrong

- If the sound device of your monitor disappears or stops after this release, set `EnableDpAudioContainerId` to 0
  and restart Windows. Then tell us what happened.
- If a Vulkan game starts badly or draws wrongly, delete `%LOCALAPPDATA%\mesa_shader_cache` and start it again. If
  that helps, set `MESA_SHADER_CACHE_DISABLE=true` for the game and tell us.
- If Quake II RTX or another ray tracing program loses its graphics device, send us the support report with the
  name of the program and the mode you ran.
- If a game has a black screen or a wrong picture in full screen, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for that game and start it again. Then tell us what happened.
- If a game fails after you change a graphics setting, set the setting back to "Application decides" on the page
  where you changed it.
- If a game warns about an old graphics driver, turn on the AMD-format driver version on the Graphics page of
  amdgpu-wddm Control and restart Windows.
- If Windows stops with stop code 0x116 after a GPU job stops, send us the support report. It holds the driver
  log and the result of each recovery.
- Send us the support report from amdgpu-wddm Control. It holds the driver log and the stored graphics settings.
