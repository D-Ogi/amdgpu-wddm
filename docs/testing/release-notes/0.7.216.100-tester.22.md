# amdgpu-wddm 0.7.216.100-tester.22

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.216.100-tester.21. This release replaces it. The notes of 0.7.216.100-tester.21
list the changes since 0.7.216.100-tester.20, and they apply to this release too, with the changes below.

## New

- The installation now sets how long Windows waits for the graphics before it resets them. It writes 10 seconds,
  the waiting time the lab board runs. Windows waits 2 seconds when nothing sets the value, which is short for a
  heavy picture on this board: with 2 seconds a long frame can end the game, and it can stop Windows. You do not
  have to write the value by hand any more. The new waiting time applies after the restart of Windows that the
  installation asks for.
- amdgpu-wddm Control shows the waiting time on the Help page, under "Waiting time for the graphics", and lets you
  choose 2, 5, 10, 20, 30 or 60 seconds. The app says what is saved now, and that a new waiting time works after you
  restart Windows. The recovery view ("amdgpu-wddm Control (recovery)") shows the waiting time as well, and names
  the page where you change it. The "?" button next to the setting explains it, and the settings search finds it
  under words such as "freeze" or "black screen".
- "Restore default graphics settings" also puts the waiting time of the release back.
- Quake II RTX runs with path tracing, in both of its ray tracing modes. The driver computed one address of the
  ray tracing data structure wrongly, and the GPU then ran until Windows reset it, about 27 seconds after the
  start of the game (issue #34). The lab ran the full path-traced renderer on this package. The 1280x720
  timedemo finishes with both ray-tracing APIs: 631 frames in 10.56 s (59.74 fps) with
  `VK_KHR_ray_tracing_pipeline`, and 631 frames in 10.71 s (58.93 fps) with `VK_KHR_ray_query`. A driven session
  of 240 s at 1920x1200 ran to its own time bound, with a good picture. Through all three runs the driver
  reported no hang recovery attempt, no 4101 event of the Windows graphics stack, no GPU fault and no fence
  timeout. Peak Tctl was 85.0 C and the wall power peaked at 175 W. Measured on unit A, 2026-10-09, package
  0.7.216.100-tester.22.
- A full-screen or borderless Direct3D 12 game now puts its own picture on the screen, and the desktop compositor
  does not copy each frame. This is on after the installation. The driver asks for it only when the size of the
  game's picture is a screen resolution the monitor offers, and it keeps the old path for every other case.
- The setting for the frames that the processor may prepare ahead now works in Direct3D 12 games as well. Before
  this release it worked in Direct3D 11 games only. A game that already keeps fewer frames ahead is left as it is.
- The kernel-mode driver is version 0.7.216.23.

## Fixed

- A Direct3D 12 program that uses multisample (MSAA) render targets starts. Before this release the driver refused
  the memory alignment such a render target needs, and the program stopped at its start with an out-of-memory
  error that was not one (issue #33).
- In a 32-bit Direct3D 11 program the VSync setting Off now removes the frame rate limit that the program sets
  itself, and VSync On holds the refresh rate of the screen in every program. The driver now offers the newer
  Direct3D 11 interface, through which Windows passes the whole setting of a frame.

## Known issues

- The driver log still keeps only about 6 minutes of events on an idle desktop. The driver writes its regular
  status lines every 60 seconds, but one line for each memory move that the driver makes for a program fills the
  log in their place. A support report can therefore miss an event of some minutes ago (issue #29).
- A program that the router sends to the processor path gets Direct3D feature level 10_0 only. With the release
  setting gpu-default this affects programs whose image the router cannot resolve. Keep the router at gpu-default
  (issue #24).
- The 64-bit Vulkan driver keeps no shader cache on disk. A Vulkan game compiles its shaders again at each start
  (issue #10).
- Without administrator rights, `bc250kmd_cli clock read` gives no clock and no temperature. Use
  `bc250kmd_cli dpm` in its place (issue #7).
- After a processor trial of the Tuner ends or you reset it, the processor boost can stay at 3.2 GHz until the next
  Windows restart. The boost goes back to 3.5 GHz only when the processor is busy at the start of the trial
  (issue #26).
- The desktop compositor composes a full-screen game again while another window covers part of it, for example a
  notification. The driver has no overlay path for such a window yet.
- A screenshot or a screen recording of a full-screen Direct3D 12 game can be black. The game puts its own
  picture on the screen, and the compositor does not get the frames. The lab saw a black screenshot of a game
  in a borderless window. To record such a game, set `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for it.
- The known issues of 0.7.216.100-tester.21 apply, except the ones this release answers: the MSAA render targets
  (issue #33), Quake II RTX (issue #34), VSync Off in 32-bit programs, the frames that the processor may prepare
  ahead, and `TdrDelay` (issue #12), which the installation now sets.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.
- `TdrDelay` is a Windows value (`REG_DWORD`, seconds) under
  `HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers`. This release writes 10 there. The app writes only
  numbers between 2 and 60, and it never removes the value: a value that is absent would get the default of the
  release again at the next installation. A waiting time that you set yourself, in the app or by hand, stays as it
  is. A waiting time that an earlier installation of ours wrote gets the new default. The uninstaller writes the
  value from before the installation again, or removes it when there was none. Windows reads the value when it
  starts, so every change of it applies after a restart of Windows.
- The game's own picture on the screen is on for Direct3D 12 games. `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off`
  in the environment of a game, or the same text in the `Experiment` value of the game under
  `HKLM\SOFTWARE\amdgpu-wddm\D3D12\Applications\<program file name>`, gives the path of
  0.7.216.100-tester.21 back for that game.
- The newer Direct3D 11 interface is on for all Direct3D 11 programs.
  `AMDGPU_WDDM_D3D11_EXPERIMENT=wddm22-ddi-off` in the environment of a program, or the same text in the
  `Experiment` value of the program under `HKLM\SOFTWARE\amdgpu-wddm\D3D11\Applications\<program file name>`,
  gives the interface of 0.7.216.100-tester.21 back for that program. The VSync setting then works as it did in
  that release.
- The graphics settings are `REG_DWORD` values under `HKLM\SOFTWARE\amdgpu-wddm\Graphics` for all games and under
  `HKLM\SOFTWARE\amdgpu-wddm\Graphics\Applications\<program file name>` for one game. No value is set after the
  installation, so each game keeps its own settings until you change one.

## If something goes wrong

- If a game has a black screen or a wrong picture in full screen, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for that game and start it again. Then tell us what happened.
- If Quake II RTX or another ray tracing program loses its graphics device, send us the support report with the
  name of the program and the mode you ran.
- If a Direct3D 11 program is worse than in 0.7.216.100-tester.21, set
  `AMDGPU_WDDM_D3D11_EXPERIMENT=wddm22-ddi-off` for that program and start it again. Then tell us what happened.
- If a game fails after you change a graphics setting, set the setting back to "Application decides" on the page
  where you changed it.
- If Windows stops with stop code 0x116 after a GPU job stops, send us the support report. It holds the driver
  log and the result of each recovery.
- Send us the support report from amdgpu-wddm Control. It holds the driver log and the stored graphics settings.
