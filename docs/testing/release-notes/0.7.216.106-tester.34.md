# Nagi (amdgpu-wddm) 0.7.216.106-tester.34

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It
replaces 0.7.216.105-tester.33.

It is signed with our **test certificate** and still requires Windows test-signing mode.

## How to install

Copy `amdgpu-wddm-setup-0.7.216.106-tester.34.exe` to a local folder and double-click it. Or unpack the zip file
and double-click `setup.exe` in the folder it makes. You can install this release over tester.33: you do not have
to uninstall first. Windows reports the driver package version as 40.7.216.106, which
is higher than 40.7.216.105 of tester.33.

## New

- **Game profiles in files.** An administrator can now give one program its own driver options without a new
  driver. Put the profile in a file in `C:\ProgramData\amdgpu-wddm\profiles` (on the drive of the Windows folder).
  Each file has the format of its upstream project, so a profile entry from that project goes into the file as it
  is: `drirc.d\*.conf` for the Vulkan driver (Mesa drirc), `dxvk.conf` for Direct3D 11 (DXVK) and
  `vkd3d-proton.conf` for Direct3D 12 (vkd3d-proton). The program reads the files when it starts. The driver reads
  a file only when only administrators can change it. `README.txt` in the folder tells how to set the owner when the
  driver refuses a file.
- **Per-game rules now apply on Windows.** The Vulkan driver now matches the rules of its built-in game and engine
  list on Windows: earlier, no rule that names a game by a pattern or an engine applied. Direct3D 11 now gives the
  Vulkan driver the name of the game and of its engine, so that these rules find Direct3D 11 games too. The built-in
  DXVK profiles of Direct3D 11 and Direct3D 12 games now set their frame rate limit, their VSync and their maximum
  frame latency. A value that you set in the control app or in the registry stays first. The driver now also finds
  the engine of a Direct3D 12 game from its program file, reads the memory overflow setting in 32-bit programs, and
  accepts a program path longer than 260 characters.
- **The graphics settings of the control app now also apply to Vulkan and OpenGL games.** VSync, the frame rate
  limit, anisotropic filtering and the maximum frame latency, for all games or for one game, now also apply to
  64-bit and 32-bit Vulkan games and to 64-bit OpenGL games. Earlier, only Direct3D 11 and Direct3D 12 games read
  them.
- **Direct3D 12 stream output is complete.** A program can now capture the clip and cull distances of vertex and
  domain shaders, and the built-in outputs and the colours of the geometry shader streams 1 to 3.
- **Direct3D 11 games in full screen can now show their frames directly.** The Direct3D 11 driver now asks for a
  frame buffer that the screen can show without the desktop composition, as the Direct3D 12 driver does. Before,
  it did so only when a registry value that no tool wrote was set. To turn it off, set the DWORD `ScanoutPrimary` to
  0 under `HKLM\SOFTWARE\amdgpu-wddm\D3D11`.
- **zstd for the shader disk caches.** The Vulkan driver (64-bit and 32-bit) and the OpenGL driver now compress
  their shader disk cache with zstd at level 3 instead of zlib at its highest level.
- **The Direct3D 11 shader cache has a size limit.** The shader cache folder of Direct3D 11 now keeps at most 2 GiB
  for all games together. When it is full, the files of the game that you played longest ago go first. The files of
  a game that runs are never deleted.
- **A smaller Direct3D 12 shader cache.** In a user account, the Direct3D 12 cache of a game now keeps only the
  identifiers of its shaders, and the Vulkan driver keeps the compiled shaders in its own cache. The Direct3D 12
  cache folder `%LOCALAPPDATA%\amdgpu-wddm\vkd3d` now keeps at most 1 GiB, and the games that you played longest ago
  go first. A game can now turn its driver cache off and on, or clear it. The driver reports its automatic disk
  cache to a game only when that game gets it.
- **The Performance page of the control app now shows the size of the Direct3D 11 and Vulkan shader caches.**
  Earlier it showed "Cannot be checked yet" for both.
- **Recovery from a GPU timeout when the graphics chip is idle.** When Windows resets the whole graphics chip after a
  timeout, the driver used to fail that reset every time, and Windows stopped with `0x116`. Now, when the driver can
  stop all work of the chip and every engine is idle, the reset succeeds and Windows continues. In every other case
  Windows stops with `0x116` as before. To turn this off, open a command prompt as administrator, run
  `bc250kmd_cli state set AdapterRecoveryMode 0` and restart the computer.
- **Higher clocks for your cooler.** The Graphics page of the control app has a new card, "Higher clocks for your
  cooler". It asks which cooler is on your board and shows three warnings. With an air cooler you can then set up to
  2200 MHz for the graphics and 3900 MHz for the processor, with an all-in-one liquid cooler up to 2300 MHz and
  4100 MHz. The standard limits (2000 MHz and 3500 MHz) do not change by themselves: after the restart, choose the
  higher clocks yourself. The thermal rules stay the same: the driver lowers the clocks when the chip reaches 87 °C.
  Some boards switch off their power completely under heavy load at high clocks. Such a board starts again only
  after you pull out the power cable for a short time. After such an unexpected stop the driver turns the higher
  limits off and the control app tells you. The card is only on a BC-250 board. `bc250kmd_cli oc` shows the tier in
  force.
- **FSR 4 in Direct3D 12 games that include it.** A game that ships AMD's FSR 4 upscaler file
  (`amd_fidelityfx_upscaler_dx12.dll`, version 4.x) can now use FSR 4 on the BC-250. The driver gives that file the
  identity of a Radeon RX 6700 series chip (Navi 22), so the file selects its FSR 4 path for that family of chips
  (the INT8 path). Before, the file found no FSR 4 path for this chip and used FSR 3.1. We tested the FSR 4.1.2 file
  of the AMD FidelityFX SDK 2.4.0. A game that ships only FSR 3.1 or older, or has FSR built into its program file,
  does not change. The identity is only for that one query of AMD's files: Windows, the driver and the other
  graphics files of the game still see the BC-250.
- **The control app has a switch for it: "Allow FSR 4 in games that include it".** It is on by default. You can set
  it for all games or for one game, as the other graphics settings. Restart the game after a change.
- **Games with anti-cheat protection never get FSR 4**, also when the switch is on, because their protection can
  see a changed identity. The list: Counter-Strike 2 (`cs2.exe`), Apex Legends (`r5apex.exe`, `r5apex_dx12.exe`),
  Fortnite (`FortniteClient-Win64-Shipping.exe`), PUBG: BATTLEGROUNDS (`TslGame.exe`, `TslGame_BE.exe`), Rainbow Six
  Siege (`RainbowSix.exe`, `RainbowSix_BE.exe`), Escape from Tarkov (`EscapeFromTarkov.exe`,
  `EscapeFromTarkov_BE.exe`), Destiny 2 (`destiny2.exe`) and VALORANT (`VALORANT-Win64-Shipping.exe`). For any other
  game with anti-cheat protection, set the switch to off on the page of that game.
- **The scan-out engine of the graphics chip draws the mouse pointer.** Before, Windows drew the pointer into the
  picture of the desktop, and each move of the mouse made Windows draw a new frame. Now the pointer is a separate
  layer that the scan-out engine puts on top of the picture. When only the mouse moves, Windows does not draw a new
  frame. On the BC-250, with the pointer moving over an idle desktop, the Windows desktop process (DWM) now uses about
  half the processor time (62 ms each second, before 120 ms), and the driver gets about 1.5 frames a second, before
  about 60. When a window moves under the pointer, the cost is the same as before.
- **It is on by default.** You do not have to do anything.
- **The control app has a switch for it: "Hardware mouse pointer" on the Graphics page.** If the pointer flickers,
  jumps or has wrong colours, set the switch to off. Then Windows draws the pointer again, as in earlier releases. A
  change works after you restart Windows.
- The driver supports pointers up to 256 x 256 pixels, all three pointer types of Windows (black-and-white, colour, and
  colour with a mask), large accessibility pointers, and a turned screen.

## Fixed

- **Rise of the Tomb Raider no longer stops at a black screen when it starts.** The Vulkan driver of the Direct3D 12
  path waited for the graphics chip inside a submission, while the chip waited for a later submission of the game.
  In our tests the game reached its main menu in 5 of 5 starts, with no click.
- **GOG Galaxy no longer shows a white window without content.** Direct3D 11 lost its device when the window came
  back from the notification area, and then could not make a new one. Direct3D 11 now keeps the device, opens the
  shared surfaces of the browser part of Galaxy, and reports only success or a device loss from Present.
- **3DMark Time Spy no longer loses its device in the demo and Graphics test 1.** The rule that keeps the Direct3D 12 engine
  away from a descriptor problem of this graphics chip did not apply on Windows. It now does.
- **Direct3D 12: a custom border colour in a compute shader read as 0.** It now has the value that the program set.
- **The Vulkan driver for Windows Vulkan programs got two fixes of the Direct3D path:** shaders now get the padding
  that the instruction prefetch of this chip needs, and the driver no longer uses GDS memory that it did not set up.
  This is in the 64-bit and the 32-bit Vulkan driver.

- **Direct3D 12: an ExecuteIndirect with a command signature for more than 4096 mesh draws lost the whole command
  list.** The driver now draws the commands that the count buffer names.
- **Direct3D 12 shader caches in a folder with letters outside the code page of Windows**, for example a user name
  with Polish, Japanese and Cyrillic letters together, now work.
- **You can go back to an earlier tester release after you uninstall this release.** The earlier release then
  starts with its default settings. The setup of the earlier release no longer stops at `state prepare failed (exit 13)`.
- **When you uninstall tester.31v3, tester.32 or tester.33 and then install this release, your settings stay.**
  This release reads the settings that the uninstall of these releases kept.

## Known issues

- **Update from tester.31 or tester.31v2 on Windows 11 24H2 or later:** until the update is complete, the old driver
  is still installed, and Windows Security can make the desktop flicker. The Smart App Control button of the setup
  window opens Windows Security. Before you start the setup, open PowerShell as administrator and run:

  ```powershell
  $k='HKLM:\SOFTWARE\amdgpu-wddm\AppRouter'; if (!(Test-Path $k)) { New-Item $k -Force | Out-Null }; $d=@((Get-ItemProperty $k -ErrorAction SilentlyContinue).Deny) + 'sechealthui.exe' | ? { $_ } | Select-Object -Unique; New-ItemProperty $k -Name Deny -PropertyType MultiString -Value $d -Force | Out-Null
  ```

  This adds Windows Security (`sechealthui.exe`) to the list of applications that always draw on the processor. It
  keeps the entries that are already in the list. It has an effect immediately, without a restart. An update from
  tester.31v3, tester.32 or tester.33 does not need it.
- **Small, stretched desktop after the start:** some boards start the screen in a small scaled mode, for example
  800x600 on a 2560x1440 screen. The driver then keeps that one mode. To get the native resolution, open a command
  prompt as administrator, run `bcdedit /set {globalsettings} highestmode on` and restart the computer.
- A passive adapter that does not identify itself works only when it is connected at the start of Windows.
- Do not use hibernation: the first resume can crash Windows with `0x116`. Set the power button to "Shut down".
- **Some Direct3D 12 games stop for up to one second** while they compile shaders, also in places you visited
  before. Clair Obscur: Expedition 33 does this. We work on it.
- **This release does not offer Ollama.** An Ollama that you installed with an earlier release stays installed.
  llama.cpp is offered as before.
- **A hang of the compute queue that the driver cannot stop** still stops Windows with `0x116`, as for a hang of the
  graphics queue.
- **A pixel shader that writes to memory at 8 or 16 samples** can also write for pixels at the edge of a triangle
  that the triangle does not cover. At 1 and 4 samples, and at sample frequency, it does not. Earlier releases also
  have this problem.
- **Direct3D 12 ignores ForcedSampleCount when a render target or a depth buffer is bound.** Earlier releases also have
  this problem.
- **Vulkan: the query counters of geometry shader primitives and of generated primitives read 0** on this graphics
  chip. The other pipeline statistics have their values.
- **Direct3D 12 stream output:** when a program draws a geometry shader stream 1, 2 or 3 and all its streams
  together need more than 8 clip and cull distances, that stream gets no clip or cull distance.
- **Indirect draws: the driver reports at most 4096 draws in one indirect draw call** (Vulkan
  `maxDrawIndirectCount`). The mesh shader path of this chip records each draw on the processor, so a higher limit
  would make each such call record all its draws, whatever its count.
- **When a Direct3D 12 game clears its driver cache**, the shared cache of the Vulkan driver
  (`%LOCALAPPDATA%\mesa_shader_cache`) stays. To clear it, delete that folder while no game runs.
- **32-bit Vulkan games:** VSync off stops only the wait for the desktop composition, because their picture goes
  through GDI, which cannot tear. The maximum frame latency has no effect there, because such a game can never
  queue more than one frame.
- **Game profiles: the driver reads only the options of each format that this route can use.** DXVK options of
  DXVK's own swap chain and of the adapter identity (for example `dxgi.customVendorId`, `dxgi.maxDeviceMemory`,
  `dxgi.enableHDR`) have no effect, because Windows' own DXGI does that work. A program name in a file must be
  exact, with the same upper and lower case letters. vkd3d-proton cannot name a program file whose name has
  letters outside ASCII.
- **A tool that reads AMD's identity data, for example a monitoring tool, can show the revision of a Radeon RX 6700
  series chip** instead of the revision of the BC-250. That is the identity that lets FSR 4 start. It does not change
  the graphics chip, its clocks or the driver. For a Direct3D 12 program, set "Allow FSR 4 in games that include it"
  to off for that program, and the program sees the revision of the BC-250.
- AMD's frame generation does not change: only the upscaler uses the new identity.

## Settings affected

- The installation keeps the settings that you changed.
- The installation makes the folder `C:\ProgramData\amdgpu-wddm\profiles` with `README.txt`. An uninstall keeps
  the folder, because its files are yours.
- New settings: `AdapterRecoveryMode` (0 off, 1 or 2 on, 2 when absent) and the overclock tier `OcTier` (0 standard,
  1 air cooler, 2 liquid cooler, set by the control app). The upper limits of `DpmMaxMHz`, `CpuMaxMHz` and
  `CpuUvSteps` are higher only when a tier is in force.
- New setting: `FsrUpgrade` (DWORD, 1 on, 0 off, on when absent) under `HKLM\SOFTWARE\amdgpu-wddm\Graphics` for all
  games and under `HKLM\SOFTWARE\amdgpu-wddm\Graphics\Applications\<program file>` for one game. The control app
  writes it. The installation does not write it.
- New setting: `EnableHardwarePointer` (DWORD) under
  `HKLM\SYSTEM\CurrentControlSet\Services\bc250kmd\Parameters`. 1 is on, 0 is off. When the value is not there, the
  driver uses on. The driver reads it when it starts. The control app writes it (on deletes the value, off writes 0).
  The installation does not write it.

## Tested

Host tests on the build computer, with no GPU, on the files of this release:

- Every component build of this release passed its host tests: the Direct3D 11 and Direct3D 12 engine tests, the
  Vulkan queue and submission tests (1203 checks, 0 failures), the Direct3D 11 DDI and draw tests, and the new tests
  for the shader cache policy, the shader cache size limit and the per-game settings.
- The application router test passed 96 scenarios with 0 failures, with the desktop drivers of this release.
- The files of this release hold none of the diagnostic setting names that a release build must not read.
- Host tests: the anti-cheat list (also with shortened program names), the order of the rules, the identity data,
  and the setting that the Direct3D 12 driver sends to the kernel driver.
- Host tests: the conversion of each pointer type to the format of the scan-out engine, the life cycle of the pointer
  (start, mode change, stop, the pointer shape that arrives between two mode changes), and the mode plan with
  and without the pointer (the pointer does not change which screen modes the driver accepts).

Tests on a BC-250 with Windows 11:

- With this release installed, a Direct3D 12 test program with the FSR 4.1.2 upscaler file of the AMD FidelityFX
  SDK 2.4.0 got FSR 4 with the switch on. Started with the program file name of a game on the anti-cheat list, it got
  FSR 3.1.6, also with a game program name of 20 characters. There were no crashes and no GPU timeouts.
- On a BC-250 with Windows 11, with the hardware pointer on and with it off, each after a restart of Windows:
  - A camera looked at the screen with a 256 x 256 test pointer at five places. At each place the pointer was at
    the same position and with the same size, on and off, with no frame or other marks around it.
  - At each place the pointer registers of the scan-out engine had the position, size and shape that Windows gave.
  - 60 seconds of mouse moves over the desktop, and 60 seconds with a window that moves under the pointer: the
    processor time of DWM and the frames that the driver got (the numbers above).
  - No crashes, no GPU timeouts and no restarts of DWM.
- With this release installed and the hardware pointer on (the default), a camera saw the test pointer at the
  centre and at the lower right of the screen, and the driver log had the lines of the pointer. During 1250 mouse
  moves over the desktop, DWM made 1.6 frames per second. On the idle desktop it made 1.2.
