# amdgpu-wddm 0.7.216.100-tester.21

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.216.100-tester.20. This release replaces it. The notes of 0.7.216.100-tester.20
list the changes since 0.7.216.100-tester.19, and they apply to this release too, with the changes below.

## New

- When a GPU job stops and does not continue, the driver now stops only that job. The program of the job loses its
  graphics device, and the desktop and the other programs continue. Before this release Windows stopped with stop
  code 0x116 after each such job, because this GPU cannot reset as a whole. In our test the program got the error
  `DXGI_ERROR_DEVICE_HUNG` and Windows did not stop.
- The desktop part of the driver now waits for the GPU in steps of 1 second. While the driver stops a job of
  another program, the desktop keeps its graphics device. In our test the screen did not go black, and the desktop
  compositor kept its process and its device.
- The driver reads the name and the display modes of your monitor through the DisplayPort cable. Windows gets the
  real name of the monitor, and the Windows display settings offer resolutions that are smaller than the native one.
  The signal on the cable keeps the native timing of the monitor. The display hardware scales a smaller resolution
  to fill the screen and keeps its aspect ratio.
- The Display page of amdgpu-wddm Control changes the resolution and the GPU scaling. After a change, Control asks
  you to keep it. If you do not answer in 15 seconds, the old setting comes back.
- The sound device of the DisplayPort monitor now gets the name, the speakers and the audio formats that the monitor
  reports.
- The display hardware can now put the picture of a game on the screen directly in the colour formats R8G8B8A8
  and R10G10B10A2. Before this release it did this with B8G8R8A8 pictures only. When the game stops, the driver
  sets the B8G8R8A8 format again.
- amdgpu-wddm Control has a new page for graphics settings. You can set them for all games, or for one game on the
  Games page. The settings are a frame rate limit, vertical sync (VSync), anisotropic filtering, the number of frames
  that the processor can prepare ahead, a performance overlay and the processor route for a Direct3D 11 game. A
  change applies at the next start of the game.
- A setting for all games makes the driver report a version number in the AMD format. Use it for a game that warns
  about an old graphics driver.
- Direct3D 12 programs get shader model 6.8. Before this release they got shader model 6.6. If a game fails with
  the new shader model, choose 6.7 or 6.6 for that game on the Games page.
- The `tools` folder holds `d3d11bench.exe`, a short Direct3D 11 test. It draws, fills and runs shaders, and it
  prints a checksum of the picture.
- The kernel-mode driver is version 0.7.216.22.

## Fixed

- The Ascent starts with Direct3D 12. Before this release the game stopped at its start with
  `DXGI_ERROR_DEVICE_REMOVED`, also with ray tracing off. The driver refused a ray tracing pipeline that the game
  makes from parts, and the refusal removed the device (issue #27).
- A Vulkan program, a Direct3D 11 program or a Direct3D 12 program can now use more memory than the GPU budget.
  Windows moves other data to system memory. Before this release such a program lost its device at its next GPU job
  when it needed more than about 8 GB of GPU memory (issue #28).
- The driver log keeps more time. Before this release the driver wrote its regular status lines every 5 seconds,
  and the log kept only about 5 minutes of events. Now the driver writes them every 60 seconds while the GPU is at
  its idle clock (issue #29).
- A change of the screen resolution no longer clears the confirmed state of a driver start. Before this release a
  mode change of a game or of Windows made amdgpu-wddm Control report the start as not confirmed (issue #30).
- After a processor trial of the Tuner ends or you reset it, the processor boost goes back to the 3.5 GHz of the
  firmware. Before this release it stayed at 3.2 GHz until the next Windows restart (issue #26).
- The VSync setting of Graphics settings now limits a Direct3D 11 program in a window to the refresh rate of the
  screen. This applies to 64-bit programs, and to the setting On in 32-bit programs.

## Known issues

- In a 32-bit Direct3D 11 program, the VSync setting Off does not remove the frame rate limit that the program sets
  itself. VSync On works.
- The setting for the frames that the processor can prepare ahead has an effect on Direct3D 11 programs only. A
  Direct3D 12 game controls this value itself.
- A program that the router sends to the processor path gets Direct3D feature level 10_0 only. With the release
  setting gpu-default this affects programs whose image the router cannot resolve. Keep the router at gpu-default
  (issue #24).
- The 64-bit Vulkan driver keeps no shader cache on disk. A Vulkan game compiles its shaders again at each start
  (issue #10).
- Without administrator rights, `bc250kmd_cli clock read` gives no clock and no temperature. Use
  `bc250kmd_cli dpm` in its place (issue #7).
- The known issues of 0.7.216.100-tester.20 apply, except the one about the processor boost after a processor
  trial (issue #26). The issue about `TdrDelay` changes: a GPU job that runs longer
  than `TdrDelay` now stops only its own program, as "New" tells. Windows stops with stop code 0x116 only when the
  driver cannot stop the job. Keep `TdrDelay` at 10 (issue #12).

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.
- `HangRecoveryMode` is a new `REG_DWORD` value under the driver service's `Parameters` key. The installation writes
  1, and the driver uses 1 when the value is absent. 1 lets the driver stop one GPU job that does not continue. 0
  gives the behaviour of 0.7.216.100-tester.20.
- `EnableDisplayModes` is a new `REG_DWORD` value under the same key. The installation writes 2. 2 offers the modes of
  the monitor and scales the smaller ones. 1 reads the monitor but puts the smaller modes in the centre of the
  screen without scaling. 0 gives the one mode of 0.7.216.100-tester.20.
- `EnableScanoutPlaneFormats` is a new `REG_DWORD` value under the same key. The installation writes 1. 0 gives the
  B8G8R8A8 pictures only, as in 0.7.216.100-tester.20.
- The graphics settings are `REG_DWORD` values under `HKLM\SOFTWARE\amdgpu-wddm\Graphics` for all games and under
  `HKLM\SOFTWARE\amdgpu-wddm\Graphics\Applications\<program file name>` for one game. No value is set after the
  installation, so each game keeps its own settings until you change one.

## If something goes wrong

- If Windows still stops with stop code 0x116 after a GPU job stops, send us the support report. It holds the driver
  log and the result of each recovery.
- If the screen stays black or has a wrong picture after a resolution change, wait 15 seconds: the old setting
  comes back. If that does not help, write 0 into `EnableDisplayModes` and restart Windows. Then tell us what
  happened.
- If a game has wrong colours in full screen, write 0 into `EnableScanoutPlaneFormats` and restart Windows. Then
  tell us what happened.
- If a game fails after you change a graphics setting, set the setting back to "Application decides" on the page
  where you changed it.
- Send us the support report from amdgpu-wddm Control. It holds the driver log and the stored graphics settings.
