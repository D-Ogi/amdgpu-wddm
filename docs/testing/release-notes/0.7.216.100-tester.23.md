# amdgpu-wddm 0.7.216.100-tester.23

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.216.100-tester.22. This release replaces it. The notes of 0.7.216.100-tester.22
list the changes since 0.7.216.100-tester.21, and they apply to this release too, with the changes below.

## New

- The 64-bit Vulkan driver now keeps its shaders on disk. A Vulkan game compiled every shader again at each start.
  From this release the second start of the same game reuses what the first start compiled (issue #10). The cache
  lives in `%LOCALAPPDATA%\mesa_shader_cache` and grows as you play. A program that runs under a system account,
  such as the desktop itself, gets no cache directory and no cache. PLACEHOLDER-VALIDATION: the measured second
  start of Quake II RTX, its pipeline-compile counts and the size the cache reaches go here after the lab session.
- Ray tracing in a 64-bit Vulkan game gets two corrections that the Direct3D driver of this project already had.
  A ray that an any-hit shader rejects on a procedural shape no longer leaves the rejected hit's data behind. A game
  that builds its ray tracing shaders in pieces finds them in its own shader cache again at the next start, instead
  of compiling them anew.
- The kernel-mode driver is version 0.7.216.24.

## Fixed

- The driver log keeps a useful history again. One line for each memory move that the driver makes for a program
  filled the log in minutes, so a support report could miss what happened a few minutes ago. The driver now writes
  the first of those lines and then one summary line with a count, and the status block that amdgpu-wddm Control
  asks for no longer pushes the log out of the way (issue #29).
- The processor boost comes back after a trial of the Tuner. The boost could stay at 3.2 GHz until the next Windows
  restart, because the driver read the clock of the moment and an idle processor runs at 3.2 GHz. The driver now
  measures the boost ceiling of your processor and restores that. While the ceiling is unknown the driver refuses a
  clock limit instead of taking one it could not give back, and a refused clock limit no longer costs the undervolt
  that you saved (issue #26).
- The setting of amdgpu-wddm Control that reports the driver version in the AMD format works. The driver wrote the
  version to a key that Windows had not made yet at that moment, so the setting had no effect and a game could
  still warn about an old graphics driver. The driver now writes the adapter's own software key, which is the key
  Windows tells a graphics driver to write. Turning the setting off puts the installed version number back, as
  before.
- A 64-bit Vulkan game no longer ends without a message when an internal check of the driver fails. The Vulkan
  driver of every release up to 0.7.216.100-tester.22 shipped with its development-time checks switched on, and
  such a check ends the game process on the spot. This release switches them off, as the Direct3D driver of this
  project always did.

## Known issues

- A program that the router sends to the processor path gets Direct3D feature level 10_0 only. With the release
  setting gpu-default this affects programs whose image the router cannot resolve. Keep the router at gpu-default
  (issue #24).
- Without administrator rights, `bc250kmd_cli clock read` gives no clock and no temperature. Use
  `bc250kmd_cli dpm` in its place (issue #7).
- The desktop compositor composes a full-screen game again while another window covers part of it, for example a
  notification. The driver has no overlay path for such a window yet.
- A screenshot or a screen recording of a full-screen Direct3D 12 game can be black. The game puts its own
  picture on the screen, and the compositor does not get the frames. To record such a game, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for it.
- The known issues of 0.7.216.100-tester.22 apply, except the ones this release answers: the driver log (issue
  #29), the processor boost after a Tuner trial (issue #26), the shader cache of the 64-bit Vulkan driver (issue
  #10) and the setting that reports the driver version in the AMD format.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.
- The shader cache of the 64-bit Vulkan driver is on. `MESA_SHADER_CACHE_DISABLE=true` in the environment of a
  program turns it off for that program, and `MESA_SHADER_CACHE_DIR` puts the cache somewhere else. Deleting
  `%LOCALAPPDATA%\mesa_shader_cache` is safe at any time: the next start compiles again and fills it.
- The setting that reports the driver version in the AMD format is `ReportAmdDriverVersion` (`REG_DWORD`) under
  `HKLM\SOFTWARE\amdgpu-wddm\Graphics`. 1 reports the AMD-format version, 0 or no value reports the installed
  version number of this release. The value takes effect at the next start of the graphics driver, which means a
  Windows restart. amdgpu-wddm Control owns the setting.
- `TdrDelay` stays as 0.7.216.100-tester.22 set it: this release writes 10 seconds, keeps a waiting time that you
  set yourself, and the uninstaller puts the earlier value back.
- The graphics settings are `REG_DWORD` values under `HKLM\SOFTWARE\amdgpu-wddm\Graphics` for all games and under
  `HKLM\SOFTWARE\amdgpu-wddm\Graphics\Applications\<program file name>` for one game. No value is set after the
  installation, so each game keeps its own settings until you change one.

## If something goes wrong

- If a Vulkan game starts badly or draws wrongly after this release, delete `%LOCALAPPDATA%\mesa_shader_cache` and
  start it again. If that helps, set `MESA_SHADER_CACHE_DISABLE=true` for the game and tell us: the shader cache is
  new in this release for the 64-bit Vulkan driver.
- If Quake II RTX or another ray tracing program loses its graphics device, send us the support report with the
  name of the program and the mode you ran.
- If a game has a black screen or a wrong picture in full screen, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=scanout-flip-off` for that game and start it again. Then tell us what happened.
- If a Direct3D 11 program is worse than in 0.7.216.100-tester.22, set
  `AMDGPU_WDDM_D3D11_EXPERIMENT=wddm22-ddi-off` for that program and start it again. Then tell us what happened.
- If a game fails after you change a graphics setting, set the setting back to "Application decides" on the page
  where you changed it.
- If a game warns about an old graphics driver, turn on the AMD-format driver version on the Graphics page of
  amdgpu-wddm Control and restart Windows.
- If Windows stops with stop code 0x116 after a GPU job stops, send us the support report. It holds the driver
  log and the result of each recovery.
- Send us the support report from amdgpu-wddm Control. It holds the driver log and the stored graphics settings.
