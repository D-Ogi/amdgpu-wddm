# amdgpu-wddm 0.7.215.100-tester.18

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.213.102-tester.17.

## New

- Direct3D 9 programs and games now get a GPU device. They run through D3D9On12, the Direct3D 9 layer of Windows,
  on our Direct3D 12 driver. Before this release, a Direct3D 9 program found our placeholder driver `bc250umd.dll`,
  which cannot open the GPU, and it got no device.
- 32-bit Direct3D 12 programs now get our driver. The package has 32-bit builds of the Direct3D 12 driver, its
  engine and its Vulkan driver in the folder `wow64\d3d12`. 32-bit Direct3D 9 programs use D3D9On12 on this driver,
  as 64-bit Direct3D 9 programs do.
- The driver now sets the speed of the case fan while it runs. By default it uses its own curve. This curve turns the
  fan at least as fast as the BIOS "Standard Mode" curve, and at full speed from 85 C. When the driver stops (shut
  down, restart, driver update, a crash), it gives the fan back to the board, and the board's own curve runs the fan
  again. The driver never changes the BIOS "Fan Setting" option.
- amdgpu-wddm Control has a Case fan card on the Performance page. Select one of five modes: Automatic (the board
  runs the fan), Driver curve (the default), Quiet, Performance or Custom. A chart shows the curve, and you can move
  its points with the mouse or the keyboard. The card can also run a fan test of 10 seconds at one speed. After the
  test, the fan goes back to the mode that you selected.
- The driver reads the power of the chip once each second from the chip's own power manager. amdgpu-wddm Control
  shows this value in the Power row. Before this release the row said "No reading".
- amdgpu-wddm Control has "Advanced tuning" on the Graphics page. The section stays closed until you open it. It sets the voltage curve
  of the GPU clock, and the clock limit, the undervolt, the temperature limit and the number of cores of the
  processor. Each change is a trial: the driver takes it back by itself, unless you keep it. Use these settings only
  if you know what they do.
- When two or more programs use the GPU at the same time, the work of one program does not wait any more until the
  GPU finishes all the work of the other program.
- The driver prepares the DisplayPort audio device of your monitor for Windows. This is the first part of sound over
  DisplayPort. No sound comes out of the monitor in this release.
- The support report has a line for the fan control: who runs the fan, and why the driver last gave the fan back to
  the board.
- The kernel-mode driver is version 0.7.215.1. The number 0.7.214 names part of the same work. We released no driver
  with that number.

## Fixed

- Direct3D 10.0 programs use the GPU driver, as Direct3D 11 programs do. The notes of 0.7.213.102-tester.17 said
  that they still get the processor driver and feature level 10_0. That was wrong on Windows 11: Windows opens our
  driver for a Direct3D 10.0 program in the same way as for a Direct3D 11 program. The setting `AppRouter` `Mode`
  (default `gpu-default`) and the lists `Allow` and `Deny` decide for both. This applies to 64-bit and to 32-bit
  programs.

## Known issues

- We did not test this package on the BC-250 yet. The fan control, the power reading, the DisplayPort audio part
  and the shared GPU work of two programs passed our tests on a computer without a BC-250 only. One test program got
  a Direct3D 9 device on the lab computer. The 32-bit Direct3D 12 driver and the Direct3D 10.0 route ran only on a
  computer with another GPU.
- No Direct3D 9 game and no Direct3D 10.0 game has run on an installed package yet.
- Close HWiNFO, Open Hardware Monitor, AIDA64, MSI Afterburner, FanControl or a similar tool before you trust a fan
  value. Such a tool can read or set the same fan chip at the same time as the driver. Then both readings can be
  wrong, and the fan speed can change between the two settings.
- We did not measure the direct screen path on this board. The desktop driver of this release always answers no
  to that question, as in the release before this one.
- The Vulkan driver for 64-bit Vulkan programs is the build of 2026-09-27, as in the releases before this one. It
  copies each frame through the processor, and it has no shader disk cache. 32-bit Vulkan programs get the newer
  build. Direct3D 11 and Direct3D 12 programs are not affected: they get the newer build.
- After a crash or a power loss the driver closes the GPU desktop path, and the processor draws the desktop (slower
  animations). "Reopen the GPU desktop path" on the Recovery page of amdgpu-wddm Control opens it again.
- Secure Boot must be off, and Windows runs in test mode, because we sign the driver with a test certificate. The
  desktop then has the words "Test Mode" in its corner.
- The installation needs internet access for the AMD GPU firmware, or a folder with the firmware files
  (`INSTALL.md`, section "GPU firmware").
- The Microsoft Visual C++ 2015-2022 Redistributable (x64) must be installed.
- After each logon, a small blue window confirms the driver start for about one minute. Do not close it.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.
- The package does not install `bc250umd.dll` any more. An install over an earlier release removes it from
  `C:\Windows\System32` and `C:\Windows\SysWOW64`. If a program has the file open, Windows removes it at the next
  restart.
- The installer writes an empty first entry (the Direct3D 9 entry) into `UserModeDriverName` and
  `UserModeDriverNameWow` in the GPU's software key. It writes a fourth entry (the Direct3D 12 entry) into
  `UserModeDriverNameWow`, which names `wow64\d3d12\amdgpu_wddm_d3d12.dll`. `verify.cmd` reads both values back (lines
  `D3D registration` and `32-bit D3D/Vulkan`).
- The 32-bit Direct3D 12 driver reads the same program profiles as the 64-bit driver
  (`HKLM\SOFTWARE\amdgpu-wddm\D3D12\Applications`).
- Each new change of the driver has one setting that takes it away. All five are `REG_DWORD` values under the
  driver service's `Parameters` key. 1 is the new default. Write 0 and restart Windows to go back to the behaviour of
  the release before this one for that change only:
  - `EnableFanControl`: 1 lets the driver set the case fan. 0 means that the driver never sets the fan, and the
    board's own curve runs it. The fan reading stays (`EnableHwmon`).
  - `EnableSmuMetrics`: 1 reads the power of the chip. 0 means no power reading.
  - `EnableVmidPool`: 1 lets the work of two programs run without the wait. 0 gives the wait of the release before
    this one.
  - `EnableDpAudio` and `EnableDpAudioEndpoint`: 1 prepares the DisplayPort audio device. `EnableDpAudio` 0 means
    that the driver does nothing for audio. `EnableDpAudioEndpoint` 0 does the same for the preparation of the
    device only.
- `FanMode`, `FanProfile` and the `FanCurve` values under the same key are your fan choice. They are absent after
  the installation, which means the Driver curve. The driver writes them when you select a fan mode in amdgpu-wddm
  Control.
- The settings of the release before this one keep their meaning and their defaults.

## If something goes wrong

- If the fan does not behave as you expect, select Automatic on the Case fan card. The board then runs the fan with
  its own curve. If that does not help, write 0 into `EnableFanControl` and restart Windows.
- Send us the support report from amdgpu-wddm Control. It holds the driver log and the fan control line.
