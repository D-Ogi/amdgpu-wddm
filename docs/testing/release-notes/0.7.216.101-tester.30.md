# Nagi (amdgpu-wddm) 0.7.216.101-tester.30

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and Nagi Control App of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes two records
that only this installer and this control program read.

The release before this one is 0.7.216.100-tester.29v2. This release replaces it. The notes of
0.7.216.100-tester.29v2 list the changes since 0.7.216.100-tester.29, and they apply to this release too, with the
changes below.

## How to install

Take one of the two downloads. The single file `amdgpu-wddm-setup-0.7.216.101-tester.30.exe` holds the whole
package: copy it to a local folder and double-click it. Or unpack the whole zip file to a local folder, then
double-click `setup.exe` in the folder it makes. The setup window asks for administrator rights itself. It reads the
state of the computer and shows what it will change. Your click on Install is your consent, and the window asks
nothing more. It restarts Windows by itself after a countdown of 15 seconds, and it continues after each logon. On
the command line, run `files\install.cmd` from the unpacked folder as administrator, with all its switches.
`INSTALL.md` in the package gives all ways.

- The kernel-mode driver is version 0.7.216.63. Its driver package has the date 10/13/2026 and the version
  0.7.216.101. Tester.29v2 has the same date, and Windows keeps an installed driver package that a new one does not
  rank above, so this release takes the next version number.

## New

- **The Direct3D and Vulkan drivers that games use now build shaders on a stack of their own.** Release
  0.7.216.100-tester.29v2 did this for the desktop files only. There, the desktop (`dwm.exe`) of Windows 24H2 and
  25H2 builds its shaders on a thread with a small stack, and the shader compiler needs more than that stack holds.
  The compiler now moves to a larger stack that it reserves and checks itself before it builds a shader or a
  pipeline. This release does the same in the Direct3D 12, Direct3D 11 and Vulkan drivers, 64-bit and 32-bit. We
  saw the stack overflow in the desktop only, not in a game. A program that builds shaders on a thread with a small
  stack can no longer stop for this reason.

## Fixed

- **On a board with the 8-core processor unlock, the driver no longer uses broken numbers from the chip's
  measurement table.** The driver reads a table of power, voltage, clock and temperature numbers from the chip
  once a second. The fan uses its power number, and the driver log and Nagi Control App show the others. Reports
  from the community say that on a board with the 8-core unlock and the original chip firmware, the numbers of
  cores 6 and 7 overwrite other fields of that table, among them the GPU clock and the GPU temperature. The
  driver now checks every table before it uses it. A field that the chip did not write, a number outside its
  range, or the pattern of those overwritten fields refuses the table. The driver then keeps the last good table.
  After three refused tables in a row, it stops reading the table until the next start. The fan then follows its
  temperature curve without the power number, and the driver log says why the table was refused. Our own board has
  six cores, so we could test the check only with recorded and constructed tables, not with an unlocked board.
  Please tell us what the driver log says on yours.

- **Windows Explorer no longer closes with an error when the driver stops.** The driver stops when you update or
  remove it, or when you disable the GPU in Device Manager. Explorer then asked our Direct3D 11 driver for more
  work, that request failed, and the cleanup after the failure read a part of the request that did not exist yet.
  The cleanup now finds every part ready, and Explorer gets the normal "device removed" answer. The same fix is in
  the Vulkan drivers, 64-bit and 32-bit, and in the driver that draws the Windows desktop.

- **The support report of Nagi Control App holds the startup diagnostics again.** In 0.7.216.100-tester.29v2 the
  part of the program that collects them stopped before it wrote a line, and the report said only "Worker exit
  -532462766." Now it writes every section. When one check fails, the report names the error and the other checks
  still run.

- **The support view no longer says that the start confirmation task is not installed when it is.** Nagi Control
  App runs without administrator rights, and Windows does not let such a program read this task. The view now says
  that it cannot read the task from there, and it shows the result of the task's last run from its log.

- **Recent games no longer lists web browsers and Windows programs.** Every program that uses Direct3D appears in
  that list, Microsoft Edge and the Snipping Tool too. Nagi Control App now hides browsers, store clients and the
  programs of Windows. "Show hidden games" lists them, and "Show" puts one back in your games.

## Known issues

- **On a board with the 8-core unlock, the power numbers can be missing.** When the driver refuses the measurement
  table, Nagi Control App shows no power numbers, and the fan takes no extra speed for a high load. The temperature
  still drives the fan, and the emergency rule at high temperature stays on. The GPU clock control does not use this
  table, so it is not affected.

- The known issues of 0.7.216.100-tester.29v2 apply.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.

- This release adds no setting and changes no default. `DpmMaxMHz`, `SubmitWatchdogMs`, `FanLoadBoost`,
  `EnableDpAudioContainerId`, `HangRecoveryWaves`, `EnableRingVmFlush`, `CuMode` and `TdrDelay` stay as
  0.7.216.100-tester.29v2 set them.

## If something goes wrong

- When the driver does not start, send us the text file that the installer names at the end of its run, or the
  support file of the setup window, which holds the same text.

- If a game or program that ran on 0.7.216.100-tester.29v2 stops at its start or while it loads shaders on this
  release, tell us. The stack change of this release touches every shader build.

- On a board with the 8-core unlock, send us the support report from Nagi Control App. Its driver log holds the
  reason for each refused measurement table.

- Look at the preview of a support file before you send it. When you find personal data in it, do not send the
  file, and tell us in the report so that we can fix the application.
