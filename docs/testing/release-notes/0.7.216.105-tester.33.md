# Nagi (amdgpu-wddm) 0.7.216.105-tester.33

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It
replaces 0.7.216.104-tester.32.

It is signed with our **test certificate** and still requires Windows test-signing mode.

## How to install

Copy `amdgpu-wddm-setup-0.7.216.105-tester.33.exe` to a local folder and double-click it. Or unpack the zip file
and double-click `setup.exe` in the folder it makes. You can install this release over tester.32: you do not have
to uninstall first. Windows reports the driver package version as 40.7.216.105, which
is higher than 40.7.216.104 of tester.32.

## New

- **Ray tracing tier 1.2 with opacity micromaps in Direct3D 12.** A game that uses the Agility SDK can now attach
  opacity micromaps to its triangles: the driver can use that opacity data during ray traversal. The driver reports raytracing tier 1.2 to these games.
- **Shader model 6.9 in Direct3D 12, with shader execution reordering.** A game that uses the Agility SDK now gets
  shader model 6.9. The driver offers the newest Direct3D 12 driver interface, version 0120, to the Agility SDK.
  Shader model 6.9 brings shader execution reordering (a ray tracing shader can sort its work before it shades the
  hits) and long vectors. Windows' own Direct3D 12 stays on the earlier interface and shader model.
- **Enhanced barriers and relaxed format casting in Direct3D 12.** A game that uses Agility SDK 1.619 or later now
  finds both. Clair Obscur: Expedition 33 no longer stops with an out-of-memory message because of a texture with
  several formats.
- **Mesh shaders in Direct3D 12.** The driver now offers mesh and amplification shaders (Mesh Shader Tier 1) to
  Direct3D 12 programs.
- **A separate compute queue for Vulkan and Direct3D 12.** Compute work now runs on a separate hardware compute queue
  of the graphics chip, in parallel with the graphics work. A Vulkan program finds a compute-only queue family next
  to the graphics queue. Direct3D 12 games run the work of their compute and copy queues there too. Windows shows it
  as a third engine of the GPU, "Compute0". To turn the compute queue off, clear "Second queue for calculations" on
  the Graphics page of the control app. All work then uses the graphics engine.
- **Direct3D 12 work graphs (tier 1.0).** The driver enables work graphs by default for Direct3D 12 programs that use the Agility SDK. Work graphs in 32-bit programs are not tested yet.
- **Kernel GDI hardware acceleration.** The driver sends supported GDI drawing operations to the graphics chip. Other GDI operations retain their existing path. It is on by default. To turn it off, clear "Hardware acceleration of
  classic Windows drawing" on the Graphics page of the control app. The change takes effect after a restart.
- **Rendering without outputs at up to 16 samples.** Direct3D 12 and Vulkan programs can now draw without any render
  target and still count 16 samples per pixel, for example for a visibility or a coverage pass. In Direct3D 12 this
  is ForcedSampleCount and the sample counts that a draw without outputs supports.
- **Direct3D 12: a sampler heap of 4096 samplers.** A shader-visible sampler heap can now hold 4096 samplers instead
  of 2048, each with its own border colour.
- **An ADL compatibility library for programs that use AMD AGS.** Some games and samples load AMD's AGS library, and AGS needs AMD's ADL
  library. When ADL was missing, these programs stopped at the start. The driver now installs its own ADL for
  64-bit and 32-bit programs. It reports the graphics chip, its memory, the driver version and the screens. It
  reports no other AMD software feature.
- **Direct3D 12: ray tracing acceleration structures can be serialized.** A program can now save an acceleration
  structure to memory and load it again, for example to keep it between two runs.
- **Newer graphics code.** Every Mesa part of the driver uses the Mesa graphics code of 2026-10-23: Direct3D 12,
  Direct3D 11, the Vulkan driver for 64-bit and 32-bit Vulkan programs, the desktop, the software (CPU) path and
  OpenGL.
- **More user-mode components are now compiled with Clang.** This includes the desktop router,
  the control app, the 32-bit Direct3D 11 and Vulkan parts and the Direct3D 12 engine. You do not have to do
  anything.

## Fixed

- **The graphics chip gets back to full speed after a stall.** In tester.32, the chip could need about half a minute
  to get back to its full speed after a game stopped for a moment. It now returns to the last speed that the game
  needed.
- **The Direct3D 12 engine refused a hull shader that has no control-point outputs**, and the device was then lost.
  The engine now accepts such a shader.
- **Windows could stop with `VIDEO_MEMORY_MANAGEMENT_INTERNAL` (0x10E)** when a program used much graphics memory
  for a long time. The driver no longer reports a failure of its memory paging work to Windows as a success, and it
  keeps its own work out of the paging ring.
- **Direct3D 12 games used part of the system memory for driver work** that the graphics memory can hold. The
  driver now keeps its command buffers in graphics memory while there is enough of it.
- **Wrong colours in some Direct3D 12 textures.** The Witcher 3 Remaster showed rectangles of wrong colour or noise
  in some textures. The driver now uses the small memory layout for the textures that a game places in its own
  memory.
- **Shader inputs between pixel centres.** Some shader inputs that a program reads between pixel centres were
  computed at the wrong place. Direct3D 12 had this fix already. It now applies to Vulkan programs too.
- **Ray tracing hits rounded the position inside a triangle wrongly** in some cases. A miss or an empty hit object
  now gives the values that Direct3D 12 specifies.
- The driver refuses a private capability query that has a size it does not expect.

## Known issues

- **Update from tester.31 or tester.31v2 on Windows 11 24H2 or later:** until the update is complete, the old driver
  is still installed, and Windows Security can make the desktop flicker. The Smart App Control button of the setup
  window opens Windows Security. Before you start the setup, open PowerShell as administrator and run:

  ```powershell
  $k='HKLM:\SOFTWARE\amdgpu-wddm\AppRouter'; if (!(Test-Path $k)) { New-Item $k -Force | Out-Null }; $d=@((Get-ItemProperty $k -ErrorAction SilentlyContinue).Deny) + 'sechealthui.exe' | ? { $_ } | Select-Object -Unique; New-ItemProperty $k -Name Deny -PropertyType MultiString -Value $d -Force | Out-Null
  ```

  This adds Windows Security (`sechealthui.exe`) to the list of applications that always draw on the processor. It
  keeps the entries that are already in the list. It has an effect immediately, without a restart. An update from
  tester.31v3 or tester.32 does not need it.
- **Small, stretched desktop after the start:** some boards start the screen in a small scaled mode, for example
  800x600 on a 2560x1440 screen. The driver then keeps that one mode. To get the native resolution, open a command
  prompt as administrator, run `bcdedit /set {globalsettings} highestmode on` and restart the computer.
- A passive adapter that does not identify itself works only when it is connected at the start of Windows.
- Do not use hibernation: the first resume can crash Windows with `0x116`. Set the power button to "Shut down".
- **Some Direct3D 12 games stop for up to one second** while they compile shaders, also in places you visited
  before. Clair Obscur: Expedition 33 does this. We work on it.
- **You cannot go back to tester.31 after you uninstall this release.** The tester.31 setup then stops at "freeze
  state writers and publish the protected state handoff" with `state prepare failed (exit 13)`: it does not accept
  the saved settings of this newer release. Install this release again, or keep it installed.
- **This release does not offer Ollama.** An Ollama that you installed with an earlier release stays installed.
  llama.cpp is offered as before.
- **A hang of the compute queue cannot be undone.** When a program hangs the compute queue and the driver
  cannot stop its work, Windows stops with `0x116`, as for a hang of the graphics queue.
- **A pixel shader that writes to memory at 8 or 16 samples** can also write for pixels at the edge of a triangle
  that the triangle does not cover. At 1 and 4 samples, and at sample frequency, it does not. Earlier releases also
  have this problem.
- **Direct3D 12 ignores ForcedSampleCount when a render target or a depth buffer is bound.** Earlier releases also have
  this problem.
- **Rise of the Tomb Raider can stop at a black screen when it starts.** The game then waits for the graphics chip,
  and the chip waits for the game. In our tests, a click in the game window continued it once. When it does not, close
  the game and start it again. Other Direct3D 12 games that wait for work of a second queue can do the same. Earlier
  releases also have this problem. We work on it.
- **Direct3D 12: a custom border colour reads as 0 in a compute shader.** In a graphics shader the border colour
  has the value that the program set.
- **3DMark Time Spy stops Windows with `0x116`.** In our test the stop came while the demo loaded. Do not run Time
  Spy with this release. Earlier releases also do not complete Time Spy.
- **GOG Galaxy can show a white window without content**, for example when you open it again from the notification
  area. Close Galaxy completely (also in the notification area) and start it again.

## Settings affected

- The installation keeps the settings that you changed.
- The Graphics page of the control app has a new "Driver features" card with two switches: "Second queue for
  calculations" (the compute queue) and "Hardware acceleration of classic Windows drawing" (GDI). Both are on by
  default. A change takes effect after a restart.

## Tested

On our BC-250 (Windows 11 23H2, 24 compute units unless stated), with the files of this release, as published:

- An installation on a clean system, an update over tester.32, and an uninstall followed by a new installation each
  completed, with no GPU fault, no driver reset and no stop of Windows. After the update, the desktop ran on the
  graphics chip.
- Rise of the Tomb Raider (Direct3D 12, preset High, 1920x1080) completed its benchmark twice: 62.7 FPS on the first
  run, when the shaders were compiled, and 88.6 FPS on the second. With 40 compute units and compiled shaders it gave
  103.2 FPS (tester.32 with 40 compute units: 105.1 FPS).
- Quake II RTX ran with ray tracing pipelines (64.1 FPS) and with ray queries (66.4 FPS) at 1280x720, and ran its
  demo in a loop at 1920x1200 to the end of the test, with no hang and no driver reset. With 40 compute units: 90.9
  and 94.5 FPS (tester.32: 89.4 and 95.2 FPS).
- The Witcher 3 Remaster (Direct3D 12, ray tracing on) loaded a save and ran for about three minutes in the world.
  We saw no defect in the picture.
- Clair Obscur: Expedition 33 started without the out-of-memory message, loaded a save and ran in the world. We saw
  no defect in the picture.
- Direct3D 12 with the Agility SDK: shader model 6.9 and raytracing tier 1.2 in 64-bit and 32-bit programs, and the
  vkd3d-proton tests for shader execution reordering, opacity micromaps, ray tracing and border colours, with no
  failure except the compute border colour (Known issues). Our set of 155 Direct3D 12 samples and tests passed,
  with one exception: a work graph test whose expected value is wrong (Microsoft's runtime gives the same answer).
  Mesh shaders, the compute queue, 32-bit Direct3D 12 and the ADL library for AGS programs passed their tests.
- The control app shows the two new switches on its Graphics page.
- 3DMark Time Spy did not pass: Windows stopped with `0x116` while the demo loaded (Known issues).
