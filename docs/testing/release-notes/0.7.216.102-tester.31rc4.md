# Nagi (amdgpu-wddm) 0.7.216.102-tester.31

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and Nagi Control App of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes two records
that only this installer and this control program read.

The release before this one is 0.7.216.101-tester.30. This release replaces it. The notes of
0.7.216.101-tester.30 list the changes since 0.7.216.100-tester.29v2, and they apply to this release too, with the
changes below.

## How to install

Take one of the two downloads. The single file `amdgpu-wddm-setup-0.7.216.102-tester.31.exe` holds the whole
package: copy it to a local folder and double-click it. Or unpack the whole zip file to a local folder, then
double-click `setup.exe` in the folder it makes. The setup window asks for administrator rights itself. It reads the
state of the computer and shows what it will change. Your click on Install is your consent, and the window asks
nothing more. It restarts Windows by itself after a countdown of 15 seconds, and it continues after each logon. On
the command line, run `files\install.cmd` from the unpacked folder as administrator, with all its switches.
`INSTALL.md` in the package gives all ways.

- The kernel-mode driver is version 0.7.216.64. Its driver package has the date 10/13/2026 and the version
  0.7.216.102. Tester.30 has the same date, and Windows keeps an installed driver package that a new one does not
  rank above, so this release takes the next version number.

## New

- **Nagi Control App can write a log file for a game.** A game or program that does not work as you expect can now
  be recorded. You turn the switch on in Nagi Control App, you start the game, and the driver writes what it does
  into a file for you to send us. The switch runs for a time that you choose and then stops by itself, so a log
  cannot fill your disk: each file stops at 64 megabytes, and every program that starts while the switch is on
  gets a file of its own. "Stop now" ends the recording at once. The Direct3D 11, Direct3D 12 and Vulkan drivers
  all write into these files.

- **The driver now starts with 24 of the 40 graphics cores, and you choose how many to use.** 24 is the number
  that the firmware of the board switches on by itself. The Graphics page of Nagi Control App selects any number
  from 24 to 40 in steps of two. It can also map the pairs of cores one by one, so a pair that makes the computer
  unstable can stay off.

- **A DirectX 12 game that builds its shaders while it loads now loads faster.** Such a game asks the driver for
  one pipeline after another, and each one holds a shader to compile. The driver compiled them one at a time, on
  the thread of the game that asked. It now compiles them on all the cores of the processor but one, and the game
  goes on while they are built. On our board the first load of Death Stranding fell from 498 seconds to between
  308 and 368. A game that needs a pipeline at once still waits for that one pipeline, so nothing is ever drawn
  with a shader that is not ready. "If something goes wrong" below says how to turn this off for one game or for
  every program.

## Fixed

- **The desktop now appears when the firmware starts the screen in a scaled mode.** Some boards leave a small
  picture stretched to the full size of the screen when Windows starts, for example a picture of 800 by 600 on a
  screen of 2560 by 1440. The driver refused the plan that Windows inherited from the firmware in that state, so
  the screen stayed on the Windows logo, and the third start in a row was refused by the safety rule of the driver.
  The driver now reads the geometry of the output, accepts the inherited plan, and keeps the native mode as the
  fallback. (GitHub issue 38)

- **The whole desktop no longer becomes slow while the Epic Games Launcher is visible.** With that window open the
  taskbar answered a message in about 50 milliseconds instead of 0.6, and the desktop drew only about 20 times a
  second, with the GPU almost idle. Windows copies the picture of such a window through a surface that the
  processor reads every frame, and that surface was in a memory that the processor reads slowly. It is now in the
  memory that is fast for the processor. On our board the measured answer of the taskbar with the launcher visible
  fell from 49.3 to 0.9 milliseconds. (GitHub issue 41)

- **The Direct3D 11 driver now offers only the driver interface that the graphics adapter supports.** It offered a
  newer one than the adapter reports, which the Windows compatibility tests refuse at every feature level, and
  which made one Direct3D 9 test fail to create its device. The controls of 0.7.216.100-tester.24 for the vertical
  synchronisation keep working as before.

- **The support report of Nagi Control App now holds every crash record of the last 24 hours.** It kept only the
  records whose text names a part of the graphics stack, so a game that closed itself in its own code left no
  record in the report, and a report about "the game does not start" held nothing to read. The report now keeps
  every Application Error, Application Hang and Windows Error Reporting record of the last 24 hours, newest first
  and at most 500 of them.

- **The driver package no longer carries a restart directive that Windows refuses for a graphics driver.** The
  installer asks Windows to stage the driver set and to bind it at the restart, which it does itself after the
  countdown, so the installation works as before. The package now passes the Windows driver package check. The
  installer also writes a receipt of the step that put the driver on the GPU.

- **The command-line tool writes each measurement at once.** `bc250kmd_cli dpm`, `telemetry` and `fan` write a
  line for every sample. Sent to a file, they wrote nothing until the program ended, so a program that watched the
  temperature from that file saw no line at the start of a run, or a hot sample late.

- **The installer no longer reports a wrong driver version when "Report an AMD driver version" is on.** With that
  setting on, the driver gives Windows a version number in the AMD style, for example 40.7.216.100 for our
  0.7.216.100. The last step of the installer compared the number it read with the number of the package, found
  two different numbers, and said that the driver version was wrong on a computer where the driver ran well. That
  step now reads the two records that the driver itself writes: the number of the installed package, and the
  number it gave Windows. The step passes when those records name this package, and it says in one line which
  number the driver reports.

- **Nagi Control App starts the right Quake II RTX.** The benchmark page asked Steam for the program number of
  the old demo, so the benchmark did not start on a computer with the game from Steam. It now asks for the number
  of Quake II RTX itself.

- **"Render on CPU" says what it can and cannot do.** The text of that setting promised more than the setting
  gives: the processor path does not offer all of DirectX 11, and most games made after 2012, Counter-Strike 2
  among them, do not start with it. The help text and the note beside the setting now say so, in all four
  languages.

- **The setup program no longer leaves an empty folder of its own behind.** The single file that installs this
  driver unpacks itself into a folder under `C:\ProgramData`, and that folder stayed on the disk after the run,
  empty and removable only by an administrator. The setup program now takes its folder away again when it is
  finished with it.

## Known issues

- The known issues of 0.7.216.101-tester.30 apply, the missing power numbers on a board with the 8-core processor
  unlock among them.

- **Counter-Strike 2 does not start on this driver.** The game checks every graphics module it loads, and it
  refuses ours, because the files of the driver outside the kernel do not yet carry a signature that Windows
  trusts by itself. You can tell the game to accept them in Steam: open the properties of the game and add
  `-allow_third_party_software -vulkan` to the options it starts with. The game then runs on our Vulkan driver.
  Valve writes that the first of those two options can lower your Trust Factor while it is set, so use it only if
  you accept that.

- **The DirectX 11 renderer of Counter-Strike 2 draws no picture yet.** With the two options above the game
  reaches its menu on Vulkan. On its DirectX 11 renderer it starts, and no frame appears.

- The game log is new. Tell us when a log file stays empty, when the switch does not stop by itself, or when a game
  becomes slow while the switch is on.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.

- **An upgrade from 0.7.216.101-tester.30 sets the number of graphics cores back to 24, once.**
  0.7.216.101-tester.30 could not record that you had chosen 40 yourself, so this install cannot tell your choice
  from its own default. Choose your number again after this install. From this release on, every upgrade keeps it.

- This release changes one default. `CuMode` is 24, where 0.7.216.101-tester.30 wrote 40. `DpmMaxMHz`,
  `SubmitWatchdogMs`, `FanLoadBoost`, `EnableDpAudioContainerId`, `HangRecoveryWaves`, `EnableRingVmFlush` and
  `TdrDelay` stay as 0.7.216.101-tester.30 set them. The game log is off until you turn it on, and it turns itself
  off again.

## If something goes wrong

- When the driver does not start, send us the text file that the installer names at the end of its run, or the
  support file of the setup window, which holds the same text.

- When the screen stays black or shows the Windows logo after the installation, tell us which screen and which
  resolution the firmware of the board uses. The fix of this release reads the geometry of the output.

- When a DirectX 12 game starts badly, draws wrongly or stops while it loads, set
  `AMDGPU_WDDM_D3D12_EXPERIMENT=async-pso-off` for that game and start it again. The driver then builds its
  shaders one at a time, as the releases before this one did. Then tell us what happened. The same words in the
  value `Experiment` of the registry key `HKLM\SOFTWARE\amdgpu-wddm\D3D12` hold for every program, and in
  `HKLM\SOFTWARE\amdgpu-wddm\D3D12\Applications\<name of the program>.exe` for one program.

- Look at the preview of a support file before you send it. When you find personal data in it, do not send the
  file, and tell us in the report so that we can fix the application.
