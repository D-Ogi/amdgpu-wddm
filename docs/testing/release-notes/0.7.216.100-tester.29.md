# amdgpu-wddm 0.7.216.100-tester.29

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes two records
that only this installer and this control program read.

The release before this one is 0.7.216.100-tester.28. This release replaces it. The notes of 0.7.216.100-tester.28
list the changes since 0.7.216.100-tester.27, and they apply to this release too, with the changes below.

## How to install

Unpack the whole zip file to a local folder, then double-click `setup.exe` in the folder it makes. The setup window
asks for administrator rights itself. It reads the state of the computer, shows what it will change and asks before each
restart of Windows. After each logon it starts by itself and continues. On the command line, run
`files\install.cmd` from that folder as administrator, with all its switches. `INSTALL.md` in the package gives
both ways.

## New

- **The zip file now unpacks to a folder that holds one file and one folder:** `setup.exe`, which is what you
  double-click, and `files`, which holds everything else. Up to the last release the folder held eleven files,
  four folders, and the setup window two levels down, in a folder named `setup`, which was easy to miss.

- **The setup window has the look of the control application.** The same title bar, the same colours in light and
  dark, and the same buttons. Every screen reads in English, Polish, Japanese and Korean. The window takes the
  keyboard alone, and it works with a screen reader.

- **The installer reads the Secure Boot state of your firmware and says what it found (BD-125).** The standard
  BC-250 firmware versions P2.00, P3.00 and P5.00 have no Secure Boot setting, so the state is off there and you
  do nothing. The installer now prints `off (not built into the firmware)` and names where it read that. On a changed
  firmware that does have the setting the installer stops before it changes anything and tells you where the
  setting usually is.

- **The message about the test certificate says what the installer adds and where.** It names the two certificate
  stores of the computer that get our test certificate, and it says that the uninstaller takes the certificate
  away again.

- **The graphics engine now gets the page tables of the program that draws a picture as commands in front of that
  picture**, on the engine's own command ring. Earlier releases wrote them through the registers of the chip
  before each picture. This is the setting `EnableRingVmFlush`, which 0.7.216.100-tester.24 added with the value
  off, and from this release it is on. On our test board The Witcher 3 Remaster at HIGH with ray tracing gave the
  same time for each picture with the setting on and off at the same GPU clock: 70.23 ms on and 70.33 ms off at
  1300 MHz. With the setting on, the driver reported no GPU fault, no freeze and no lost picture. One pair of
  sessions cannot show a difference smaller than about half a millisecond.

- **The driver records it when Windows stops a start that nothing confirmed.** Up to this release the driver wrote
  why a start failed, and nothing at all when the start itself went through and Windows stopped the device a
  moment later. That second case is the one in the field reports of 2026-10-11: the start reached its stage 39,
  and Windows stopped the device and showed Code 43. The driver now writes the stage before the stop, the health
  of the start, the generation of the device, the number of this boot, the times of the stop and the last 64 lines
  of its log to `HKLM\SYSTEM\CurrentControlSet\Services\bc250kmd\Parameters\StopRecord`. You do not need to turn
  anything on and you do not need a restart.

- A start that a healthy desktop confirms leaves no stop record when Windows stops the device later. An older
  record stays in place in that case, so the installer and the control application compare the number of the boot
  in the record with the number of this boot before they show it as this start's.

- A start that failed leaves no stop record either. The driver stops the device itself to undo such a start, so
  Windows stopped nothing, and the reason of that failure is in `StartRecord` with the step and the status that
  failed. The stop record therefore means one thing only: a start that reached a started device, that nothing
  confirmed, and that Windows then stopped.

- The stop record holds no reason from Windows, because Windows gives the driver none when it stops a device. Our
  tools say so in the report instead of naming a cause that nobody measured.

- **The installer collects the details by itself when the driver does not start.** The last step of the
  installation reads the state of the device, the start record, the stop record and the health of the start. When
  those readings show a driver that did not start, the installer writes one text file for that run next to its
  log. The file holds the decision and the readings behind it, the two records, the entries of the Windows system
  log of this boot from `Display`, the DirectX kernel, Plug and Play and the service control manager, the sections
  of `setupapi.dev.log` of the graphics device, and the newest files of `C:\BC250\kmdlog`. The collection takes at
  most 20 seconds and at most 4 MB. It changes no result of the installation.

- The setup window puts that file into its support file as `run-<n>-diagnostics.txt`, and the result screen says in
  your language that it collected the details. The command-line installation prints the name of the file in its
  last lines. A test run with `-DryRun` collects nothing.

- **amdgpu-wddm Control collects the same details when it starts on a driver that did not start.** It reads the
  two records and the state of the device, and it puts the result into the support report. The work runs in a
  program of its own with a time limit, so the window stays usable.

- The kernel-mode driver is version 0.7.216.39.

## Fixed

- **The driver starts when the firmware of the board scales its picture (BD-124).** The firmware of the board
  draws its own start-up picture in one size and sends it to the monitor in another size. The driver of
  0.7.216.100-tester.28 read only the size on the monitor side, so it refused such a mode and stopped with Code
  43. One field report shows the case: the firmware picture is 1024 by 768, and the link to the monitor runs at
  1920 by 1080. The driver now reads the two sizes apart. It keeps the size of the firmware picture, the size on
  the monitor side and the way the chip scales between them as one set, and it gives Windows that set. A mode that
  the driver keeps this way is never changed by the driver: it writes no scaler value and no timing value for it.

- **The driver reads the monitor data of an HDMI link and turns the sound on (BD-124).** Through a passive
  DisplayPort-to-HDMI adapter the board sends HDMI signals. The driver now reads the monitor data over the two
  data lines of such a link, so Windows learns the name of your monitor and the sizes that it offers. It also
  turns the sound of the HDMI link on. Up to this release such a link had no sound at all.

- **A serial number or a machine ID stayed in a support file and in a bug report.** The rule that removes those
  values needed a line that ends in one single character, and every log of Windows ends its lines in two. The rule
  therefore matched nothing at all, in any file of any support file or bug report of the releases up to
  0.7.216.100-tester.28. The user name, the profile path, the computer name, the MAC addresses and the e-mail
  addresses were taken out as the documents promise. The serial numbers, the machine IDs, the product IDs and the
  UUIDs were not. The rule is fixed, and a test of the application now reads the values back out of a finished
  support file.

- The same rule also missed a value behind a prefix. A line of `setupapi.dev.log`, a line of an event message and
  a line of the driver's own log carry a time or a tag in front of the word, and the rule stopped at the first
  colon of the line. It now looks past such a prefix.

- **A support file can name a second account of the computer.** The reports take out the user name and the profile
  path of the account that collects them. A log of Windows can also name another account of the same computer, and
  such a name stayed in the file. The reports now take out the account name of every other `C:\Users\<name>` path,
  the security identifiers and the computer name of an event entry.

- **`install.cmd -Console` kept only the first switch.** The command line of `install.cmd -Console -DryRun` lost
  `-DryRun`, so a test run installed for real. Every switch now reaches the installer.

- **`INSTALL.md` named the wrong command for the test mode of Windows.** The table of changes now shows
  `bcdedit /set '{current}' testsigning on`, with the quotation marks that PowerShell needs. A command prompt does
  not need them. The installer itself always passed the argument correctly.

- **`INSTALL.md` named 1500 MHz as the highest GPU clock of the automatic clock control.** The release default is
  2000 MHz.

- **A record of this start could be reported as a record of an earlier start of the computer.** When Windows stops
  the driver after a start that nothing confirmed, the driver keeps a record of that stop. The record carries the
  number of the start of Windows that wrote it, so a reader can tell a fresh record from one that an earlier start
  left behind. Windows keeps that number in two places, and the copy our readers used can stay one behind for the
  first minutes. A fresh record then read as an older one, which is the opposite of what the number is there for.
  Every reader now takes the number from the place the driver takes it from, each one says where it read it, and a
  number that is higher than the number of this start is named as such instead of as an earlier one.

- **The uninstaller of 0.7.216.100-tester.28 stopped before it removed anything.** Before it removes a file, the
  uninstaller keeps a copy of the tools that put your Windows settings back. It keeps that copy in the folder
  `C:\ProgramData\amdgpu-wddm`. It then refused that folder, because Windows lets every account of the computer
  add a file there, and because our own installer makes the folder in that way. The uninstaller therefore stopped
  on every computer, and it left the installation as it was. The folder of the recovery tools keeps its strict
  rules: no other account may write in it. For the folder above it, two rules remain: it must be a folder, and an
  administrator or the system must own it. An installation of this release also replaces the uninstaller.

## Known issues

- **The driver still offers one picture mode on an inherited link.** It is the mode that the board set at
  power-on, and a scaled mode is now one of them. You cannot select another resolution or refresh rate on such a
  link. The driver does not see a change between an adapter and a DisplayPort cable while Windows runs. Restart
  Windows after you change the cable. A direct DisplayPort cable has none of these limits.

- **The driver refuses a start when it cannot read the state of the chip,** or when that state is in the middle of
  a change. It then writes the registers that it read into the start record, so a report tells us the mode of your
  monitor.

- A stop record can be older than the Windows session that you look at it in. The installer and the control
  application say which boot a record is from. When the computer cannot report the time of its own start and the
  record holds no boot number, they say that instead of placing the record in this boot.

- Versions, file hashes and hardware IDs stay in a support file and in a bug report. We need them to tell your
  installation from another one.

- The value `Status` of a stop record is always 0. It is not a success and it is not the problem code of the
  device. The reports print it with that sentence beside it.

- `Microsoft-Windows-DxgKrnl-Operational` is off on a standard Windows. The section of that log in the collected
  file is then empty, and the file says so.

- `setup.exe` needs the folder `files` next to it. Unpack the whole zip file. Do not copy `setup.exe` out on its
  own. When the folder is missing, the first screen says so in your language instead of failing halfway through an
  installation.

- `install.cmd -Console` with no other switch, started in a window that is not an administrator window, ends in
  the setup window and not in the console. Open the command prompt as an administrator, as `INSTALL.md` says. With
  any other switch beside `-Console` the elevated run stays in the console.

- The command-line entries moved with the rest of the package: `install.cmd`, `uninstall.cmd`, `verify.cmd` and
  `prepare-offline.cmd` are in the folder `files` of the unpacked release. They work there as they did in the top
  folder. A script that names a path inside the old package needs `files\` in front of it.

- To carry the package to another computer or to a memory stick, copy the whole unpacked folder. The package
  looks for `setup.exe` as well as the files, so the folder `files` on its own reports `missing setup.exe`.

- **To remove 0.7.216.100-tester.28 without an installation of this release, set the rights of the folder first.**
  In an administrator window, run `icacls C:\ProgramData\amdgpu-wddm /inheritance:r /grant:r
  *S-1-5-32-544:(OI)(CI)F *S-1-5-18:(OI)(CI)F *S-1-5-32-545:(OI)(CI)RX`. Then run `uninstall.cmd` again. An
  installation of this release is the simpler way, because it brings the uninstaller of this release.

- The known issues of 0.7.216.100-tester.28 apply, except the two that this release fixes: the driver starts on a
  scaled firmware mode, and an HDMI link has sound.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release.

- `EnableRingVmFlush` (`REG_DWORD`) under the driver's `Parameters` key: absent or 1 is the new default. 0 sends
  the same commands as version 0.7.216.24, which is the way of the earlier releases. The installer does not write
  the value, so a computer where nobody set it gets the new default. A value that you set yourself stays, 0 too.
  The driver reads the value when it starts, so a change needs a restart of Windows.

- The driver log shows the way that the driver uses:
  `gfx: VM flush on the ring (EnableRingVmFlush), engine 1` for the new default, and
  `gfx: VM flush by MMIO before the frame (EnableRingVmFlush 0), engine 17` for 0.

- The stop record needs no setting. `KeepLog` under the driver's `Parameters` key does not change it, and the
  driver writes the record also when `KeepLog` is 0.

- `DpmMaxMHz`, `SubmitWatchdogMs`, `FanLoadBoost`, `EnableDpAudioContainerId`, `HangRecoveryWaves` and `TdrDelay`
  stay as 0.7.216.100-tester.28 set them.

## If something goes wrong

- If a game freezes or loses its picture and it did not do this with the earlier release, set the old way of the
  page tables back: run
  `reg add HKLM\SYSTEM\CurrentControlSet\Services\bc250kmd\Parameters /v EnableRingVmFlush /t REG_DWORD /d 0 /f`
  as an administrator and restart Windows. Then send us the support report and tell us whether the problem stays
  with the value 0.

- When the driver does not start, send us the text file that the installer names at the end of its run, or the
  support file of the setup window, which holds the same text.

- If your monitor shows no picture through an adapter, send us the support report. It holds the start record and
  the stop record, which name the mode that the board set at power-on.

- Look at the preview of a support file before you send it. When you find personal data in it, do not send the
  file, and tell us in the report so that we can fix the application.

- Send us the support report from amdgpu-wddm Control. It holds the driver log and the stored graphics settings.
