# Pending release-notes lines: the processor's own boost clock (KMD 0.7.216.15)

This file is not a release. It holds the tester-facing lines for the next tester release notes. The release
step copies the lines into `docs/testing/release-notes/<version>-tester.N.md` and deletes this file.

## Fixed

- After the driver took back a processor setting, the processor ran at about 3.2 GHz until the next restart of
  Windows. The firmware itself boosts one core to 3.5 GHz. The driver took the limit to go back to from the
  firmware's table of processor states, and that table stops at 3.2 GHz. The driver now also reads the clock
  that each core reports at the start, and it goes back to the higher of the two. It never goes back to more
  than 3.5 GHz. This applies when a trial of a processor setting ends, when you reset the processor settings,
  and when the experimental joint power control gives the processor its clock back.

## New

- The driver now reports the clocks of the memory, the SoC, the processor cache and each processor core from the
  firmware's own measurement table. The support report and `bc250kmd_cli dpm` show them next to the power. They
  help to find why the processor and the GPU can be slower after a restart of the GPU device without a restart
  of Windows.
- An administrator can set the value `StopDpmFloor` to 0 under the driver's `Parameters` key for a test. The
  driver then sends no message to the power firmware when it stops. The value has no effect until the device
  stops. Without the value the driver behaves as before.

## Known behaviour

- After a restart of the GPU device without a restart of Windows, the processor can stay at about 2.8 GHz until
  the next restart of Windows. This version does not fix that. Restart Windows to get the full clock back.

- The kernel-mode driver is version 0.7.216.15.
