# Pending release-notes lines: Direct3D 9 through D3D9On12 (installer)

This file is not a release. It holds the tester-facing lines for the next tester release notes. The change is in the
installer only (branch `installer/d3d9on12`); the drivers do not change. The release step copies the lines into
`docs/testing/release-notes/<version>-tester.N.md` and deletes this file.

## New

- Direct3D 9 programs and games now get a GPU device. They run through D3D9On12, the Direct3D 9 layer of Windows,
  on our Direct3D 12 driver. Before this release, a Direct3D 9 program found our placeholder driver
  `bc250umd.dll`, which cannot open the GPU, and it got no device. Windows did not change to D3D9On12 by itself.
- The package does not install `bc250umd.dll` any more. An install over an earlier release removes it from
  `C:\Windows\System32` and `C:\Windows\SysWOW64`. If a program has the file open, Windows removes it at the next
  restart.

## Known issues

- 32-bit Direct3D 9 programs need the 32-bit Direct3D 12 driver, because D3D9On12 needs a Direct3D 12 driver of
  the same bitness. That driver is in `wow64-d3d12.md`.
- No Direct3D 9 game has run on an installed package yet. The measurement is one test program on the lab
  computer.

## Settings affected

- The installer writes an empty first entry (the Direct3D 9 entry) into `UserModeDriverName` and
  `UserModeDriverNameWow` in the GPU's software key. `verify.cmd` checks both values (lines `D3D registration` and
  `32-bit D3D/Vulkan`). The change has an effect after the restart that the install asks for.
