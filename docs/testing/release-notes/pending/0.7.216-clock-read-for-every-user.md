# Pending release-notes lines: the clock and the temperature without administrator rights (KMD 0.7.216.x)

This file is not a release. It holds the tester-facing lines for the next tester release notes. The release
step copies the lines into `docs/testing/release-notes/<version>-tester.N.md` and deletes this file. The
driver's own version word does not move for this change, so the release step writes the build number of the
release that carries it into the lines below in place of "this version".

## Fixed

- `bc250kmd_cli clock read` now gives the clock, the voltage identifier and the temperature to an ordinary
  user. Before this version the driver answered "access denied" unless the prompt was an administrator's, so a
  program started by the person at the keyboard could read no temperature at all. Setting a clock
  (`bc250kmd_cli clock set`) still needs an administrator prompt, as before. The numbers themselves and every
  setting stay as they were. This closes issue #7, and with it the workaround of reading `bc250kmd_cli dpm`
  in place of `clock read`.

## For the release step

- Drop the known issue every note up to 0.7.216.100-tester.27 carries: "Without administrator rights,
  `bc250kmd_cli clock read` gives no clock and no temperature. Use `bc250kmd_cli dpm` in its place (issue #7)."
  The earlier notes keep it, because it was true of those releases.

## Known behaviour

- Read without an administrator prompt, the three numbers are the driver's latest reading and can be up to one
  second old. The driver takes a fresh reading when the last one is older than that. Read from an
  administrator's prompt, the numbers are read from the chip at that moment, as before. This is what keeps many
  programs asking at once from adding work on the chip. However many ask, the driver reads the chip no more
  often than it reads it for itself. Two callers asking at the same time are still served one after the other.

- The driver's version does not change for this fix, so the version alone does not say whether the driver you
  have answers an ordinary user. The command itself does: run `bc250kmd_cli clock read` without an
  administrator prompt and it either prints the numbers or says "access denied".
