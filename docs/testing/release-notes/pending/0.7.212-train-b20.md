# Pending release-notes lines: the b20 train driver (KMD 0.7.212.1)

This file is not a release. It holds the tester-facing lines for the next tester release notes. The release
step copies the lines into `docs/testing/release-notes/<version>-tester.N.md` and deletes this file.

The pending files of 0.7.208 and 0.7.209 next to this one describe work that is in this driver as well. This
driver is one build of all of it.

## Known behaviour

- This driver carries five changes that were written apart. None of them changes what you see until you turn
  it on. A start of this driver with no setting changed behaves as 0.7.208.1 did.
- The kernel-mode driver is version 0.7.212.1. The numbers 0.7.209 to 0.7.211 were given to the same work
  while it was written apart, and no driver with those numbers was released.

## For the lab operator, not for testers

Every value below is a `REG_DWORD` under the driver service's `Parameters` key. A value that is absent, or 0,
is the behaviour of 0.7.208.1. The driver reads all of them when it starts, so each one needs a restart of the
adapter or of Windows.

| Value | Default | What 1 does |
|---|---|---|
| `EnableDirectFlipHandshake` | absent = 0 | The driver tells the desktop's user-mode driver that it will accept a game's own picture buffer. The driver ANDs this with every other setting the picture path needs, and with the hardware it found at the start, so it can never promise a flip it would then refuse. |
| `EnableHwmon` | INF writes 0 | The driver reads the board's own fan controller. 0 means no x86 port access happens at all. |
| `HwmonBasePort` | INF writes 0 | The window to read. 0 is the built-in `0x0A20`; only `0x0A00` and `0x0A10` are admitted beside it, and every other value is refused before a port is touched. |
| `HwmonExpectId` | absent | Pins the fan controller's customer identifier, once an operator has read it. Absent means the identifier is only reported. |
| `HwmonDutyProven` | absent = 0 | Says that a lab trial proved the fan-power read-back. Until then the driver reports the number and marks it unproven. |
| `NotifyDpcInReport` | absent = 0 | The completion report calls `DxgkCbNotifyDpc` itself, and the empty scheduler DPC that only existed to bring that call about is not asked for. 0 is 0.7.208.1 exactly, which is how a session prices the two shapes against each other. |
| `HotSubmitLog` | absent = 0 | Keeps the three per-submit lines in the driver log. They wrote 3871 lines a second and overwrote 75 % of the ring, so 0 leaves them out and counts what was left out. |
| `CpuTune` | absent = 0 | Admits the processor surface. 0 means the whole surface is read-only: no mailbox message is ever sent. |
| `CpuLab` | absent = 0 | Raises the admitted processor clock from the release bound to the lab bound. |
| `CpuMaxMHz`, `CpuUvSteps`, `CpuTempC`, `CpuTrialMs` | absent | The processor settings a Keep wrote. Absent means the part runs what the firmware gives it. |
| `CpuPending`, `CpuConfirmed`, `CpuLastReason` | absent | The boot guard of those settings, and why the last start did or did not apply them. Written by the driver. |
| `CoreMask`, `CoreMaskPending`, `CoreMaskConfirmed` | absent | The processor core mask a Keep wrote, with its boot guard. Absent means the mask the part ships with. |
| `DpmCurve1000` .. `DpmCurve2000` | absent | The operator's voltage at each clock step. Absent means the driver's own table line at that clock. |
| `DpmCurvePending`, `DpmCurveConfirmed`, `DpmCurveTrialMs`, `DpmCurveLastReason` | absent | The curve's boot guard, its trial window and why the last start did or did not apply it. Written by the driver. |

One addition is always on: the ring's idle-gap histogram. Per frame it costs a `KeQueryPerformanceCounter` call
and an interlocked read at each busy and idle edge of a node, one interlocked write per acknowledged vertical
blank, and integer arithmetic on those values. It reads no hardware register, sends no firmware message, opens
no port and takes no lock of its own: both node edges already run inside the lock that owns them. It adds four
lines a node, plus one, to `bc250kmd_cli log summary`.
