# amdgpu-wddm 0.7.216.100-tester.20

A tester release of amdgpu-wddm, an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It is for
people who want to test the driver on their own BC-250 and report what happens. It is not ready for daily use.

The kernel-mode driver, the installer and amdgpu-wddm Control of this release belong together. Install the three of
them from this package, and do not mix them with the files of another release. The kernel driver writes a record that
only this installer and this control program read.

The release before this one is 0.7.216.100-tester.19. This release replaces it. The notes of 0.7.216.100-tester.19
list the changes since 0.7.215.100-tester.18, and they apply to this release too, with the changes below.

## New

- A program can now ask for more memory than the GPU has. The driver gives Windows a second place for the data of a
  program, so Windows moves old data to system memory instead of refusing the new request. In our test one program
  asked for 10.7 GB on a board with 8 GB of GPU memory. Every request succeeded and every sample of the data read
  back unchanged. Windows moved 1.75 GB of it into system memory.
- The kernel-mode driver is version 0.7.216.14.
- The command line tool `bc250kmd_cli.exe` in the `tools` folder answers a new `budget` command. It prints the
  memory budget of one program, the memory that the program uses, and the bytes that Windows moved to system memory.
- The support report of amdgpu-wddm Control names the interrupt setting of the audio part of the GPU. The setting is
  new in this release. See the next section.

## Changed

- The installer puts the audio part of the GPU on message-signalled interrupts, and it restarts that one device.
  Nothing else on your computer restarts. The uninstaller puts the old setting back. See "Fixed" below for the
  reason.
- The installation no longer overwrites a driver setting that you changed. Before this release every reinstall wrote
  its own value over yours. Now the package writes a value only when the value is absent.
- The driver keeps one log file for each start of the GPU and one for each stop. Before this release it kept a file
  for each stop only. It keeps at most 200 files under `C:\BC250\kmdlog`.

## Fixed

- Sound over DisplayPort plays at its true speed. Before this release Windows sent the samples at about a third
  of real time, and a sound took 7 to 9 seconds to start. The audio part of the GPU ran on a line interrupt, where
  its interrupts do not arrive on this board. The installer now puts that part on message-signalled interrupts, and
  our measurement reports a rate of 1.0000. After the release we listened on the lab board: a video in Edge played
  with its sound on headphones at the DisplayPort monitor, and the video ran smoothly.
- A restart of the GPU while Windows runs now keeps your desktop. Before this release the screen stayed black after
  a restart from Device Manager, and only a restart of Windows brought the desktop back. We restarted the GPU twice
  inside one Windows session and the desktop stayed both times.
- A driver update outside our installer no longer ends at Code 43. Windows Update, Device Manager and `pnputil` wrote
  the value 0 into the driver switches, but left the switch of the power controller at 1. The next start of the
  driver then asked for the power controller without its register window and failed. The driver now writes a log line
  and starts without the power controller.
- The graphics clock holds 500 MHz on an idle desktop. Before this release it moved between 500 MHz and 1000 MHz
  every few seconds. In our test the clock entered the idle point once and left it no time in 150 seconds.

## Known issues

- The joint power limit of the processor and the GPU is off in this release. The driver can lower the processor limit
  while the GPU is hot and busy, but only after you write 1 into `DpmJointGovernor`. We tested the feature once on
  the lab board and it worked. It stays off until it has more test time.
- After the driver stops the GPU without a Windows restart, the processor stays slower until the next Windows
  restart. A driver update without a restart, `pnputil /restart-device` and disabling the GPU in Device Manager all
  cause it. On the lab board, arithmetic-bound processor work ran about 2.2 times slower in this state, and The
  Witcher 3 on High ran about 20 % slower. Restart Windows after every driver install or update. The cause is not
  known yet (`docs/research/k137-kmd-stop-cpu-cap.md`, issue #6).
- After a normal install the GPU runs 24 of its 40 compute units. To use all 40, select them on the Performance
  page of amdgpu-wddm Control and restart Windows (issue #9).
- The installer does not change `TdrDelay`, so Windows keeps its default of 2 seconds. A GPU job that runs longer
  than 2 seconds can stop Windows with bug check 0x116. To prevent it, write 10 into `TdrDelay` under
  `HKLM\SYSTEM\CurrentControlSet\Control\GraphicsDrivers` and restart Windows (issue #12).
- A standard user account without administrator rights loses the driver after two restarts. Use an administrator
  account for now (issue #14).
- After a processor trial of the Tuner ends or you reset it, the processor boost stays at 3.2 GHz until the next
  Windows restart (issue #26).
- There is no OpenGL driver and no OpenCL driver. OpenGL programs get only the software OpenGL 1.1 of Windows
  (issues #8 and #18).
- The Witcher 3 (Direct3D 12) showed a black screen for a whole session once, while the game rendered. We saw it on
  an older tester release. If it occurs, start the game again and send us the support report (issue #22).
- The known issues of 0.7.216.100-tester.19 apply.

## Settings affected

- The installation keeps the settings that you changed. A setting that you did not change gets the new default of
  this release. This is new in this release, and it holds for every reinstall from now on.
- `ApertureSegmentMegabytes` is a new `REG_DWORD` value under the driver service's `Parameters` key. The driver uses
  384 when the value is absent. 256 gives the memory layout of 0.7.216.100-tester.19 byte for byte. The driver holds
  any other value inside the range 256 to 447.
- `EnableSharedResidency` is a new `REG_DWORD` value under the same key. The driver uses 1 when the value is absent.
  1 lets Windows move the data of a program to system memory. 0 gives the single memory pool of
  0.7.216.100-tester.19.
- `DpmJointGovernor` is a new `REG_DWORD` value under the same key. The driver uses 0 when the value is absent. 1
  lets the driver lower the processor limit while the GPU is hot and busy.
- `DpmIdleLeavePermille` is a new `REG_DWORD` value under the same key. The driver uses 150 when the value is absent.
  It sets the load at which the GPU leaves its idle clock.
- `MSISupported` under the audio part of the GPU is not a setting of our driver. The installer writes 1 there, and
  the uninstaller puts the old value back.

## If something goes wrong

- If a game or a program runs out of memory, write 256 into `ApertureSegmentMegabytes` and restart Windows. Then tell
  us what happened. If that does not help, write 0 into `EnableSharedResidency` and restart Windows.
- If the sound or the video is wrong, write 0 into `EnableDpAudio` and restart Windows. Then tell us what happened.
- If the desktop stays black after a restart of the GPU, restart Windows. Then send us the support report.
- Send us the support report from amdgpu-wddm Control. It holds the driver log, the memory lines and the interrupt
  setting of the audio part of the GPU.
