# Nagi (amdgpu-wddm) 0.7.216.109-tester.37

A tester release of Nagi (amdgpu-wddm), an experimental Windows 11 x64 driver for the GPU of the ASRock BC-250. It
replaces 0.7.216.108-tester.36.

It is signed with our **test certificate** and still requires Windows test-signing mode.

## How to install

Copy `amdgpu-wddm-setup-0.7.216.109-tester.37.exe` to a local folder and double-click it. Or unpack
`amdgpu-wddm-tester-0.7.216.109-tester.37.zip` and double-click `setup.exe` in the folder it makes. You can install
this release over tester.36: you do not have to uninstall first. The setup updates the installed release and keeps
the settings that you changed. Windows reports the driver package version as 40.7.216.109.

## New

- **Updates from Nagi Control App.** When a newer release is out, the Driver page of Nagi Control App shows
  **Install update**. Select it and answer Yes when Windows asks. The app downloads only the parts that changed. It
  checks that the files come from the Nagi project and are complete. Then Nagi Setup installs them. A driver update
  asks for a restart. If the new driver does not start two times, the previous driver comes back automatically, and the
  Driver page tells you. This works for the releases after tester.37. Install tester.37 itself with the setup as usual.
- **Processor temperature limit.** Nagi Control App has a new card for the processor temperature limit. The default
  limit on the BC-250 is 87 C.

## Fixed

- **No more stop with `0x50` (PAGE_FAULT_IN_NONPAGED_AREA) on the processor desktop route.** When the desktop ran
  on the processor (after an unclean end of the driver, or with the graphics desktop path switched off), Windows
  could stop at the start, at the logon screen or at a shutdown. tester.35 and tester.36 had this fault. [BD-289]
- **The fan goes back to the board's own control** at the next start when a stop of the driver could not give it
  back.
- **A monitor that the driver could not switch off cleanly** is now found again at the next connect event. When the
  driver cannot restore the screen mode, the handoff of the screen now fails instead of continuing.
- **The driver no longer starts a GPU in an unknown state.** When Windows loads the driver again after a stop that
  did not finish, the driver now keeps the GPU stopped until the next restart.
- **Setup warns when another driver uses the secure processor function (1022:143E)** of the BC-250.

## Known issues

- **On the processor desktop route the screen flickers and windows show no content.** When the desktop runs on the
  processor (see BD-289 above), the screen can go black with only the taskbar, flicker when windows open or close, and
  show window frames with empty content. Windows itself does not stop. Restart with the graphics desktop path switched
  on (the default). [BD-292]
- **After a failed power change the processor limit is not in force.** If the driver cannot complete a change of the
  power state, the processor runs at the firmware temperature limit instead of the Nagi limit until the next restart.
  We saw this only in a test of the fault path. The fix comes in the next release. [BD-293]
- **A restart can stop at a black screen.** On the BC-250 a restart can stop after Windows has shut down: the screen
  stays black and Windows does not start again. On our test unit this happened in about 1 of 20 restarts, with every
  driver version tested, and also when our driver was not running. If the screen stays black for more than 5 minutes
  after a restart, switch the PC off at the wall or at the power supply switch, wait 10 seconds and switch it on
  again. [BD-145]
- **Games with module checks do not start while test signing is on.** The tester package is test-signed, so Windows
  runs in test mode. Games that check the signatures of the modules they load, or that use kernel anti-cheat (for
  example Counter-Strike 2), refuse to start or to join servers in that mode. [BD-160]
- **Please report blank taskbar or Start bars,** with the time it happened. [BD-282]
- **Long sessions at 2000 MHz need good cooling.** If your board gets hot, set the graphics clock limit to 1800 MHz
  in Nagi Control App. In a warm room a heavy game can keep the processor at its temperature limit (87 C by default)
  for a long time. This is the limit working as designed. For a cooler board, set a lower processor temperature limit
  (85 C is the lowest).
- Do not use hibernation: the first resume can crash Windows with `0x116`. Set the power button to "Shut down".

## Settings affected

- The installation keeps the settings that you changed.

## Tested

Host tests on the build computer, with no GPU, on the files of this release:

- Every component build of this release passed its host tests, with 0 failures.
- The installer dry run on the final package passed every check.

Tests on a BC-250 with Windows 11, on the final files of this release:

- This release was installed after an uninstall. The driver started after the restart, and the start confirmation
  task ended without an error.
- The desktop on the processor route (graphics desktop path switched off): three restarts and 60 seconds of window
  changes, with no stop and no crash dump. tester.36 stopped with `0x50` at each of four restarts in the same test.
  [BD-289]
- Quake II RTX ran its time demo at 1280x720 with ray tracing pipelines (71.98 frames a second) and with ray queries
  (72.97 frames a second).
- Rise of the Tomb Raider (Direct3D 12) ran its built-in benchmark to the end at the default graphics clock limit of
  2000 MHz: 64.15 frames a second overall (Mountain Peak 84.29, Syria 53.60, Geothermal Valley 52.93). The highest
  temperature was 85.9 C. For this run, the processor temperature limit was 85 C instead of the default 87 C. Our
  test rule stops a game that stays at 87 C for 10 seconds, and in a warm room the default limit kept the processor
  at 87 C. That test rule, not a fault, stopped two earlier runs with the default limit.
