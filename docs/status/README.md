## Applicable to this driver

Each slot has one class, with a reason and a source, in `tools/docs/ddi_applicability.json`:

- Applicable: the driver must implement the slot for its declared feature set on the BC-250 and on later AMD GPUs. Only these slots are in the applicable figure.
- Optional: a real feature that the driver can implement later, for example hardware scheduling, native fences, multiplane overlays, runtime power states or content protection.
- Not applicable: not relevant to a WDDM 2.x driver with GPU virtual addressing on this class of hardware. Examples: GPU partitioning and live migration, the physical-address Render and Patch path, legacy video overlays, 8 bpp palettes and swizzling ranges.

The decisions come from the WDK headers and the Microsoft documents: the driver documents, the DDI reference and the DirectX specifications. The file names their revisions. A slot is applicable when the documents make it mandatory for a WDDM version or for a capability that the driver reports. A slot without a clear answer is also applicable. The script stops when a slot has no class or a class names no slot. Thus a new WDK slot needs a decision. In the maps, an optional slot that is not done is dotted, and a not-applicable slot is grey and cross-hatched. The README shows the applicable figure as a second badge next to the raw one. The figure is not only in the alt text, because a reader must see both figures.

## Counting rule

A slot is done when its function can return success and does work. Logs, counters, error reports, zero writes and a failure constant on every path are not work. 7 kernel-mode and 8 user-mode done slots refuse some inputs. The script reads the source and does not run the driver: done means that the code exists, not that a test passed. `status.json` gives each slot with its function, source line, reason and class.
