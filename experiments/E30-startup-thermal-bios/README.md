# E30: early-start temperature and own firmware baseline

2026-09-24. Planned before the OS transition. Windows baseline M432/134,
last read-only control M43720:53, same OS/DWM,66.4C. Goal: validate a native KMD
temperature source before SMU clock preparation and GPU startup. Also collect
L35 own AmdSetup and, only with a supported read procedure, two SPI images.

Hypothesis: the named THM_TCON_CUR_TMP GPU BAR register exposes the same current
temperature encoding as the measured host-bridge SMN/k10temp path before amdgpu
loads. A plausible constant is not sufficient: compare raw values and repeated
timed samples. If they diverge or access is unavailable, keep the native BAR
callback inactive and investigate the verified SMN or SMU metrics route.

## Procedure

1. Preserve Windows preflight and STOP state. Verify diagnostic USB label FAT32
   BC250DIAG, USB bus,64160400896 bytes, GRUB network-only default4, and loader
   hashes against the measured E29 return baseline. Notify through the overlay.
2. Rename only USB efi/boot/bootx64.off to bootx64.efi and request a normal Windows
   restart. No firmware boot entry, BIOS/CMOS/NVRAM write, reset experiment or
   blanket amdgpu sweep. This is a warm OS transition, not a cold-power control.
3. Connect via Target with the pinned Linux configuration; stream output to the
   host. Identify kernel/modules/tools, confirm no amdgpu and read k10temp. Stop
   at85C. Before any raw GPU read, confirm exact1002:13fe identity, BAR5 resource
   and PCI decoding. Use named offsets generated by regcalc and the existing
   diag.Bar read-only interface. GB_ADDR_CONFIG is the known-value MMIO control;
   inspect GRBM_STATUS as state, then sample the named THM register alongside
   k10temp. Establish the source/read procedure before expanding instrumentation.
4. Read only the specific AmdSetup runtime UEFI variable, preserving attributes,
   raw payload and hashes privately outside the repo. For SPI, inspect exact
   flashrom version/source/programmer support first and record a specific read
   procedure before access. No force, erase, write, protection change or ambiguous
   chip selection. Two full reads must match before treating them as a baseline.
   Raw NVRAM/SPI stays outside the repo under firmware/bios/unit-a/.
5. Restore the positively identified USB loader to .off, sync, and reboot to
   Windows. Retain134 and existing desktop/ICD. If the consumed one-shot selects
   display-only, verify the existing clock task then perform the established
   single PnP full-table start and GPU/display controls, without another OS reboot.

No new native SMU owner is activated by this experiment. No clock above the
existing1000MHz/820mV runtime point is requested. A failed read is preserved,
not retried with forced access. AC plug recovery is reserved for an actual hang.
Results and any deviations will be recorded with immutable evidence and STATE.

Thermal variation control: after the first bounded passive comparison succeeds,
run two CPU SHA256 workers for at most six seconds while sampling both sensors
four times per second for fifteen seconds. No GPU workload or clock write.
Check85C on every sample; workers have a hard time bound and are daemonized so
an assertion ends the process. This distinguishes a live sensor from a constant.
